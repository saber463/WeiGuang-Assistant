> 口径说明：本文档保留用于说明本地数据层首轮建设过程，不再作为当前数据库结构和离线库维护流程的正式基线。
> 当前唯一正式基线文档为：`docs/2026-05-19-药品离线库正式基线说明.md`。

## 本次迭代目标

为微光畅行项目补齐药品离线库的本地数据层基础设施，让后续 OCR 识别结果、药品 SQLite 导入、用户健康档案和风险规则都可以有统一的数据落点。

## 当前可支持的能力

- 支持药品主表、别名表、详情表、规则表和用户健康档案表的本地建模。
- 支持按关键词搜索药品主表和别名表。
- 支持根据 `drug_id` 聚合药品详情、别名和风险提示。
- 支持保存用户健康档案骨架。

## 建议后续接法

1. 先生成一份 `seed_drugs.db` 或 JSON 测试数据。
2. 在 App 启动时判断本地数据库是否为空。
3. 若为空，则导入高频药测试数据。
4. 药品识别页直接调用 `DrugRepository.searchByKeyword()`。
5. 用户档案页直接调用 `saveUserProfile()`。

## 适合并行推进的分工

- 安卓端：接数据库实例化、Repository 注入和页面联调。
- 数据端：输出 CSV/JSON 清洗结果，映射到上述五张表。
- 算法端：OCR 输出标准候选文本，交给 Repository 查询。
- 产品端：维护高频药名单和风险规则文案。

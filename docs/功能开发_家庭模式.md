## 一、背景与目标

将空壳 `FamilyModeActivity`（`onCreate` 空方法体）补全为可用的**家庭看护中心**。
遵循项目既定家庭绑定规则：
- **一用户绑多家**：本端用户可维护多位家人；每位家人生成专属配对码，供家人端绑定；
- 家人即紧急联系人：SOS 时可一键通知/拨打；
- 原生 App 全功能 + 轻量引流双端形态（本实现先行落地本地可用的原生端看护能力）。

## 二、技术方案

### 2.1 家庭看护界面（`FamilyModeScreen.kt`）

- **专属配对码**：基于「包名 + ANDROID_ID」经 SHA-256 稳定派生 6 位配对码（剔除易混淆字符），
  同一设备恒定，家人可反复绑定；
- **家人列表**：直接复用 `EmergencyContactManager` 的紧急联系人作为家人成员
  （避免另建存储，SOS 逻辑天然贯通）；
- **家人管理**：姓名 + 电话添加（同号码去重写回共享存储）；
- **看护操作**：SOS 求救、管理联系人两个入口。

### 2.2 双入口

- **独立 Activity**：`FamilyModeActivity` 经 `setContent` 渲染同一 `FamilyModeScreen`，
  `onBack` 结束自身；
- **应用内路由**：MainActivity 新增 `family` 分支，支持从首页进入，并可在本页跳转
  `sos` / `emergency_contacts`。

## 三、实现文件

## 四、验证

1. `gradlew.bat :app:assembleDebug` **编译通过（2026-08-21，exit code 0）**。
2. 首页点击"家庭模式" → 显示专属配对码与空家人列表。
3. 填写姓名/电话添加家人 → 列表出现成员（写回紧急联系人）。
4. 点击 SOS 求救 / 管理联系人分别进入对应功能。

## 五、实施记录

- **家人数据复用**：以 `EmergencyContactManager` 作为家人存储源，避免双份数据不一致；
  绑定的家人即 SOS 通知对象，看护闭环完整。
- **配对码生成**：无需账号登录即可得到稳定且易读的绑定码（`SHA-256` 派生 + 去除易混淆字符），
  适配"无网络先行落地"的轻量阶段。
- **API 修正**：SOS 按钮配色原误用 `CardDefaults.buttonColors`，已改为 `ButtonDefaults.buttonColors`。

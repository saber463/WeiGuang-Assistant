## 一、背景与目标

将项目中存在的空壳 `AccessibilityReadService`（仅 `onAccessibilityEvent`/`onInterrupt` 空方法体）
补全为可用的无障碍朗读功能，面向听障/视障用户的文字辅助朗读：

1. **通知朗读**：收到系统通知（来信、短信、闹钟提醒）时自动用 TTS 朗读通知内容；
2. **选中文字朗读**：在可编辑文本中选中文字时立即朗读所选内容。

## 二、技术方案

### 2.1 服务实现（`AccessibilityReadService.kt`）

- 基于 Android `AccessibilityService`，收到事件后分类处理：
  - `TYPE_NOTIFICATION_STATE_CHANGED`：从 `event.text`（标题）与 `Notification.extras`（`EXTRA_TEXT` 内容）拼接可朗读文本；
  - `TYPE_VIEW_TEXT_SELECTION_CHANGED`：朗读 `event.text`（所选文字）。
- **独立 TextToSpeech**：为避免与 App 内 `TtsController` 单例互相打断/抢占队列，服务使用自己的 `TextToSpeech` 引擎（中文、语速 0.9）。
- **通知去抖**：同一内容在 1.5s 内不重复朗读，防止系统重复推送造成重复播报。
- `isServiceEnabled()`：从已开启的无障碍服务列表中检测本服务是否启用，供设置页展示状态。

### 2.2 引导界面（`AccessibilityReadScreen.kt`）

- 展示服务当前启用状态、功能说明、开启步骤；
- 提供按钮跳转系统「无障碍设置」（`Settings.ACTION_ACCESSIBILITY_SETTINGS`，各版本稳定可用）——
  Android 无障碍服务**禁止应用内静默授予**，只能由用户到系统设置手动开启。

### 2.3 已有配置（无需改动）

- `AndroidManifest.xml` 已声明 `<service>` 及 `BIND_ACCESSIBILITY_SERVICE`、`@xml/accessibility_read_service` 配置资源，直接复用。

## 四、验证

1. `gradlew.bat :app:assembleDebug` **编译通过（2026-08-21，exit code 0）**。
2. 首页点击"无障碍朗读" → 进入功能页，展示当前状态与开启指引。

## 五、实施记录

- **TTS 独立引擎**：服务内自建 `TextToSpeech`，规避与 App 内 `TtsController` 并发竞争；`onInterrupt`/`onDestroy` 均释放引擎。
- **事件裁剪**：仅处理通知与文本选中两类事件，避免 `typeAllMask` 海量事件引发无效处理与重复朗读。
- **API 兼容**：`ACTION_ACCESSIBILITY_DETAILS_SETTINGS` 为 API 33+ 常量、当前编译 SDK 不含，故统一使用各版本稳定的 `ACTION_ACCESSIBILITY_SETTINGS`。

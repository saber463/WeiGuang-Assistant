# 功能开发：为首页补充「聊天」与「登录」导航入口

> 版本：v1.0 | 开发日期：2026-08-11 | 时区：UTC+8 北京时间
> 状态：**已完成**（Build Successful @ 2026-08-11）

---

## 一、背景与问题

项目开发报告中明确指出两个"代码存在但不可用"的功能模块：

1. **聊天模块**（`ChatListScreen` / `ChatDetailScreen` / `ChatRepository`）
   > "聊天页面当前未从首页配置导航入口按钮，代码存在但不可通过首页 UI 访问。"
2. **用户认证模块**（`LoginScreen` / `RegisterScreen` / `AuthViewModel`）
   > "登录/注册页面当前未从首页配置导航入口按钮，代码存在但不可通过首页 UI 访问。"

即：**功能代码已完整实现，但由于首页 `MainScreen` 的功能卡片网格 `features` 列表中缺少对应条目，用户无法从首页进入这些功能**。这是一处明确的导航接入缺陷。

---

## 二、目标

- 在首页功能卡片网格中，新增「聊天」和「登录」两个入口卡片。
- 打通从首页 → 聊天列表 → 聊天详情的完整导航链路（`chat` 路由已在 `MainActivity` 接入）。
- 打通从首页 → 登录 → 注册 的认证链路（需在 `MainActivity` 新增 `login`/`register` 路由分支）。

---

## 三、现状分析（代码实测）

### 3.1 首页入口 `MainScreen.kt`
`features` 列表当前包含 6 项：药品识别(drug)、手语识别(sign)、来电助手(call)、提醒设置(alert)、一键求救(sos)、设置(settings)。

```kotlin
private val features = listOf(
    FeatureCard("💊", "药品识别", "拍照识别药物信息", "drug"),
    FeatureCard("👋", "手语识别", "手势翻译成文字", "sign"),
    FeatureCard("📞", "来电助手", "通话实时转文字", "call"),
    FeatureCard("🔔", "提醒设置", "震动+闪光闹钟", "alert"),
    FeatureCard("🚨", "一键求救", "SOS紧急求助", "sos"),
    FeatureCard("", "设置", "个人信息与偏好", "settings")
)
```

网格采用 `features.chunked(2)` 两两一行渲染，**新增卡片只需追加 FeatureCard 条目**。

### 3.2 导航宿主 `MainActivity.kt`
`when (currentScreen)` 已包含 `chat`、`chat_detail` 分支，但**缺少** `login`、`register` 分支。需要新增。

---

## 四、实施方案

### 4.1 MainActivity.kt

新增 `login` / `register` 两个路由分支，并引入对应 Composable：

```kotlin
"login" -> LoginScreen(
    onLoginSuccess = { currentScreen = "home" },   // 登录成功返回首页
    onNavigateToRegister = { currentScreen = "register" }
),
"register" -> RegisterScreen(
    onRegisterSuccess = { currentScreen = "home" }, // 注册成功返回首页
    onNavigateToLogin = { currentScreen = "login" }
)
```

> 说明：`LoginScreen` / `RegisterScreen` 内部通过 `hiltViewModel()` 获取 `AuthViewModel`，依赖 Hilt 注入，无需手动传参。`AuthViewModel` 需确保带 `@HiltViewModel` 与 `@Inject` 构造（已由前人实现）。

### 4.2 MainScreen.kt

在 `features` 列表末尾追加两个入口卡片：

```kotlin
FeatureCard("💬", "聊天", "实时消息沟通", "chat"),
FeatureCard("👤", "登录", "账号登录与注册", "login")
```

`FeatureCard.emoji` 使用 Unicode 转义（遵循项目现有风格，避免源文件编码问题）。

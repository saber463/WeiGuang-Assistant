## 一、算法概述

微光守护处理的是听障用户最敏感的数据——家庭环境音频、跌倒检测画面、紧急联系人信息、GPS定位记录。**数据的隐私保护不是可选项，而是产品生命线。**

## 二、核心算法层详解

### 2.1 AES-256-GCM 对称加密层

#### 2.1.1 算法选择理由

| 对比维度 | AES-128-CBC | AES-256-GCM（本项目选择） |
|----------|------------|--------------------------|
| 密钥长度 | 128 bits | 256 bits（抗量子计算预研） |
| 认证机制 | 无（需额外HMAC） | 内置GCM认证标签 |
| 并行化 | 不支持 | 支持（CTR模式） |
| 填充攻击 | 易受Padding Oracle攻击 | 无填充（CTR模式） |
| 性能 | 快 | 略慢但可接受（<1ms/KB） |
| 标准化 | FIPS 197 | NIST SP 800-38D |

#### 2.1.2 GCM模式数学原理

GCM (Galois/Counter Mode) 结合了CTR模式的加密和GHASH的认证：

**加密过程**：

```
1. 初始化计数器: J0 = IV || 0³¹1  (当IV长度=96位)
2. 生成密钥流:   Si = AES_K(J0 + i)  for i = 1, 2, ..., n
3. 加密:         Ci = Pi ⊕ MSB_t(Si)
4. 认证标签:     T = GHASH(H, A, C) ⊕ E_K(J0)
```

其中：
- `K` 为256位AES密钥
- `IV` 为96位随机初始化向量
- `Pi` 为明文分组
- `Ci` 为密文分组
- `H = AES_K(0¹²⁸)` 为GHASH子密钥
- `A` 为附加认证数据（AAD）
- `T` 为128位认证标签

**安全保证**：
- 机密性：CTR模式确保密文不可区分
- 完整性：GCM标签确保任何篡改都会被检测
- 认证性：AAD确保密文与上下文绑定

#### 2.1.3 核心实现代码

```kotlin
// EncryptionManager.kt - AES-256-GCM 加密核心实现
// 文件位置: safeguard-app/app/src/main/java/com/weiguang123/safeguard/crypto/EncryptionManager.kt

@Singleton
class EncryptionManager @Inject constructor() {
    companion object {
        private const val ALGORITHM = "AES/GCM/NoPadding"
        private const val KEY_SIZE = 32      // 256 bits
        private const val IV_SIZE = 12       // 96 bits (GCM推荐)
        private const val TAG_SIZE = 128     // 128 bits认证标签
        private const val ASSOCIATED_DATA = "WeiGuang_SafeGuard_v1.0"
    }

    fun encrypt(plainText: ByteArray, key: SecretKey): String {
        val iv = generateIV()                    // 随机IV，每次加密不同
        val cipher = Cipher.getInstance(ALGORITHM)
        val spec = GCMParameterSpec(TAG_SIZE, iv)
        cipher.init(Cipher.ENCRYPT_MODE, key, spec)
        cipher.updateAAD(ASSOCIATED_DATA.toByteArray())  // AAD防重放
        val cipherText = cipher.doFinal(plainText)
        return Base64.encodeToString(iv + cipherText, Base64.NO_WRAP)
    }

    fun decrypt(encryptedBase64: String, key: SecretKey): ByteArray {
        val combined = Base64.decode(encryptedBase64, Base64.NO_WRAP)
        val iv = combined.copyOfRange(0, IV_SIZE)
        val cipherText = combined.copyOfRange(IV_SIZE, combined.size)
        val cipher = Cipher.getInstance(ALGORITHM)
        cipher.init(Cipher.DECRYPT_MODE, key, GCMParameterSpec(TAG_SIZE, iv))
        cipher.updateAAD(ASSOCIATED_DATA.toByteArray())
        return cipher.doFinal(cipherText)  // 认证失败自动抛AEADBadTagException
    }
}
```

**安全设计要点**：
1. **随机IV**：每次加密生成12字节随机IV，确保相同明文产生不同密文
2. **AAD绑定**：绑定加密上下文 `WeiGuang_SafeGuard_v1.0`，防止跨版本重放
3. **GCM认证**：128位认证标签，任何修改都会导致解密失败
4. **CSPRNG**：使用 `SecureRandom` 基于操作系统熵源

### 2.2 RSA-2048 OAEP 密钥交换层

#### 2.2.1 算法选择分析

**RSA-2048 vs ECC 对比：**

| 对比维度 | RSA-2048 | ECC (P-256) |
|----------|----------|-------------|
| 安全性 | ~112 bits 等效 | ~128 bits 等效 |
| 密钥大小 | 256 bytes (公钥) | 65 bytes (公钥) |
| 加解密速度 | 较慢 | 较快 |
| Android兼容性 | API 1+ | API 23+ |
| 行业认可度 | 极其广泛 | 增长中 |

**选择RSA-2048的原因**：项目需兼容Android 7.0+（API 24+），RSA-2048的112位等效安全性对于当前威胁模型完全足够。

#### 2.2.2 OAEP填充的数学原理

OAEP (Optimal Asymmetric Encryption Padding) 使用Feistel网络结构：

```
编码过程:
  M = 明文消息
  r = 随机种子 (基于SHA-256的MGF1生成)
  
  maskedDB = MGF1(r) ⊕ (M || 0x01 || 0x00...)
  maskedSeed = MGF1(maskedDB) ⊕ r
  
  EM = 0x00 || maskedSeed || maskedDB

解码过程:
  maskedSeed = EM[1..hLen+1]
  maskedDB = EM[hLen+1..]
  
  r = MGF1(maskedDB) ⊕ maskedSeed
  M' = MGF1(r) ⊕ maskedDB
  
  验证 M' 末尾是否为 0x01 || 0x00...
```

**安全保证**：
- 选择密文攻击（CCA）防护
- 短明文暴力破解防护
- 同密钥多明文关联分析防护

## 三、零知识架构证明

### 3.1 形式化定义

**零知识架构**：对于任意服务端存储的密文数据，服务端在多项式时间内无法以不可忽略的概率区分密文和随机比特串。

### 3.2 安全性证明（非形式化）

```
假设:
  1. AES-256-GCM 是 IND-CPA 安全的
  2. RSA-2048 OAEP 是 IND-CCA2 安全的
  3. Android Keystore 提供的随机数生成器是安全的

结论:
  服务端无法解密用户数据

证明思路:
  1. 服务端持有的数据: {EK, C}
  2. EK = RSA_Enc(PubKey_server, K_session)
     - 服务端不持有 PubKey_server 对应的私钥
     - 私钥存储在用户设备 Keystore 中
     - 因此服务端无法从 EK 恢复 K_session
  3. C = AES_Enc(K_session, plaintext)
     - 没有 K_session，C 在计算上不可区分于随机数据
     - 因此服务端无法从 C 恢复 plaintext
  4. QED: 服务端无法解密用户数据
```

### 3.3 威胁模型分析

| 威胁场景 | 防御能力 | 防御机制 |
|----------|---------|----------|
| 服务端数据库泄露 | ✅ 完全防御 | 数据全密文存储，服务端无解密密钥 |
| 中间人攻击 | ✅ 完全防御 | GCM认证标签 + AAD上下文绑定 |
| 密文篡改 | ✅ 完全防御 | GCM认证标签验证，篡改后解密失败 |
| 重放攻击 | ✅ 完全防御 | 随机IV + AAD版本绑定 |
| 设备物理丢失 | ⚠️ 部分防御 | Keystore硬件保护，需设备解锁 |
| 量子计算攻击 | ⚠️ 远期风险 | 预留算法升级接口（可切换至后量子密码） |

## 七、知识产权与开源

### 7.1 算法原创性

WeiGuang-Secure 加密引擎的以下设计为团队原创：

1. **AAD上下文绑定机制**：将加密操作绑定到特定产品版本，防止跨版本密文重放
2. **三层加密架构**：RSA密钥交换 + AES数据加密 + Keystore硬件保护，针对移动端助残场景优化
3. **离线优先密钥管理**：零网络环境下完成密钥生成、加密、存储全流程
4. **自适应密钥轮换**：基于时间/数据量/网络/安全的四维触发机制

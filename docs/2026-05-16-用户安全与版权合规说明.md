# 2026-05-16 用户安全与版权合规说明

## 1. 文档目标

这份文档专门用于约束微光畅行项目的两条底线：

1. 用户安全优先
2. 版权与授权优先

项目后续所有开发、演示、答辩和对外表述，都应以本说明为准。

## 2. 用户安全红线

### 2.1 产品定位红线

药品模块的定位只能是：

- 药品识别辅助
- 风险提醒辅助
- 无障碍信息呈现辅助

不能表述为：

- 医疗诊断
- 用药结论
- 替代医生或药师判断

### 2.2 页面文案红线

页面、播报和答辩中必须长期保留以下意思：

- 本功能仅供辅助识别与提醒
- 不能替代医生、药师、处方或正式说明书
- 命中禁忌、过敏史、孕期、儿童、老年人、慢病、多药联用时，应优先人工复核

### 2.3 高风险场景处理原则

以下场景必须提升警示级别：

- 过敏史
- 孕妇
- 儿童
- 老年人
- 慢病人群
- 多药联用
- 肝肾功能异常
- 命中禁忌或慎用字段

处理要求：

1. 必须显示高对比度警示信息
2. 必须在 TTS 文案中提醒人工复核
3. 不输出“可以服用”这类确定性结论

### 2.4 当前推荐输出口径

推荐说法：

- 建议重点核对禁忌和说明书
- 检测到高风险标签，请优先咨询医生或药师
- 当前结果仅供辅助判断，请不要替代正式医疗建议

不推荐说法：

- 可以吃
- 不可以吃
- 确认安全
- 已诊断

## 3. 数据和版权红线

### 3.1 NMPA 的正确使用方式

正确定位：

- 官方校验源
- 批准文号和标准药名参考源

禁止误导性表述：

- 不宣称“调用了 NMPA 官方开放 API”
- 不把网页查询结果包装成“官方授权数据库”

### 3.2 DataSN 的正确使用方式

正确定位：

- 可作为离线药品主库候选

前置条件：

- 必须先确认购买、授权、许可或使用范围

未确认授权前：

- 不直接对外宣称“正式集成”
- 不直接商用发布
- 不直接把相关原始资源开放再分发

### 3.3 丁香园离线资源的正确使用方式

正确定位：

- 结构参考源
- 离线包架构参考

禁止动作：

- 未授权直接打包其离线库
- 未授权二次分发其说明书资源
- 在答辩中暗示“我们已正式接入丁香园数据库”

### 3.4 tngou 的正确使用方式

当前处理原则：

- 仅作历史候选来源
- 当前不作为正式项目数据源

原因：

- 接口状态不稳定
- 字段和返回结果无法持续验证
- 可信度不足

## 4. 项目当前安全与版权策略

当前项目建议坚持以下结构：

1. `NMPA` 只做标准校验
2. `自建 CSV / SQLite` 作为比赛演示主数据
3. `DataSN` 只有在授权明确后才进入正式版本
4. `丁香园` 仅做结构借鉴，不做原始资源打包

## 5. 开发执行要求

### 5.1 代码层要求

- 药品页必须展示安全边界提示
- 风险播报文案必须保留人工复核提示
- 代码中不要出现“确认可服用”这类确定性判断
- 数据层应保留来源标识字段，便于后续追踪

### 5.2 文档层要求

后续所有文档都应明确：

- 哪些数据是示例样本
- 哪些数据只做结构参考
- 哪些数据需要授权后才能进入正式版

### 5.3 答辩层要求

建议统一说法：

- 我们采用“官方校验 + 自建离线库 + 风险提示”的无障碍辅助方案
- 当前版本重点解决信息可达性和风险提醒，不替代医疗判断
- 正式推广前会进一步完成数据授权、来源校验和专业审核

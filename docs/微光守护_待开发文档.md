## 一、项目当前状态概述

微光守护是一款面向听障人士及言语障碍群体的 Android 无障碍辅助应用，核心理念为"让沟通无界限——帮助听障人士看得见声音、说得出心意"。当前版本 v1.3 已完成手语识别、通话辅助、紧急救助（SOS）、用药识别四大核心模块的开发，技术栈涵盖 MediaPipe 手部关键点检测、TFLite 手势分类（准确率 99.28%）、Vosk 离线语音识别、ML Kit 中文字符 OCR 等。

### 2.2 BUG-001：手语识别页崩溃（已完成）

| 项目 | 内容 |
|------|------|
| **编号** | BUG-001 |
| **严重等级** | High（严重） |
| **状态** | ✅ 已完成 |
| **问题现象** | 在首页点击"手语识别"卡片后，App 立即闪退崩溃。logcat 报 `UnsatisfiedLinkError: library "libmediapipe_tasks_vision_jni.so" not found` |
| **根因分析** | 三层根因：1) AGP 8.2.0 存在 BUG，AAR 中的 .so 文件不会自动打包进 APK；2) MediaPipe tasks-vision 0.10.2 AAR 只含 arm64-v8a / armeabi-v7a / x86 三个 ABI 的 .so，不含 x86_64，模拟器主 ABI 为 x86_64 时匹配失败；3) `useLegacyPackaging=false` 时系统仅按主 ABI 提取 .so，找到部分 .so 后不再回退到次 ABI |
| **修复方案** | 1) 从 AAR 手动提取 x86 的 .so 到 `app/src/main/jniLibs/x86/`；2) `build.gradle.kts` 添加 `abiFilters += listOf("arm64-v8a", "armeabi-v7a", "x86")` 排除 x86_64；3) 设置 `useLegacyPackaging=true`；4) 模拟器 AVD 配置 `hw.camera.front` 改为 `emulated`；5) 指定 `ndkVersion = "25.1.8937393-2"` 解决 strip 任务报错；6) 移除 `gradle.properties` 中 `android.stripDebugSymbols=false` |
| **涉及文件** | `app/build.gradle.kts`、`gradle.properties`、`app/src/main/jniLibs/x86/libmediapipe_tasks_vision_jni.so`、AVD `config.ini` |
| **修复时间** | 2026-08-21 14:30 |

## 五、开发规范备注

> 以下规范为项目既定规则，后续所有开发工作须遵循。

### 5.1 文档规范

- 每新增功能或修改功能时，须创建或更新对应的文档文件，给出详细的功能描述、实现逻辑、涉及文件等信息
- 文档统一存放在 `f:\java\weiguangplus\docs\` 目录下
- 文档格式为 Markdown，编码 UTF-8

### 5.2 代码注释规范

- 每个代码文件须在文件头部添加详细注释，说明：
  - 该文件的功能职责（做什么）
  - 核心逻辑说明（怎么做的）
  - 关键设计决策的原因（为什么这样做）
- 函数级别注释须说明参数含义、返回值、副作用
- 注释应解释 WHY（为什么这样设计）而非 WHAT（代码在做什么），避免冗余复述代码逻辑
- Kotlin 文件使用 KDoc 格式注释

### 5.3 BUG 排查日志规范

- 出现 BUG 时，在项目根目录 `项目开发BUG排查日志.md` 文件中按以下模板登记：

```
### 【YYYY-MM-DD HH:MM】【BUG分类】
**问题现象**：
描述运行报错、闪退、功能异常、编译失败、接口报错等完整表现

**报错/根源原因**：
源码问题、依赖版本冲突、权限缺失、配置错误、逻辑漏洞、环境变量、数据库字段异常等

**修复解决办法**：
具体代码修改、配置调整、依赖降级/升级、权限开启、逻辑改写、清理缓存等可直接复用步骤
```

- 时间使用 UTC+8 北京时间
- 编码 UTF-8
- 出现同类 BUG 时优先查阅历史记录，无匹配方案再新增记录

### 5.4 构建验证规范

- 每次代码修改完成后，须执行构建验证再继续后续开发：

```
gradlew.bat :app:assembleDebug
```

- 构建成功后，输出 APK 路径为 `app/build/outputs/apk/debug/app-debug.apk`
- 建议在模拟器上安装 APK 并冒烟测试修改涉及的功能页面，确认无崩溃后再标记任务完成

### 5.5 Git 提交规范

- 提交前确认 `gradlew.bat :app:assembleDebug` 构建通过
- 不提交 `app/build/` 目录下的构建产物
- 不提交包含密钥/Token 的配置文件（如 `local.properties` 中的 API Key）
- 提交消息使用中文，简明描述修改内容和目的

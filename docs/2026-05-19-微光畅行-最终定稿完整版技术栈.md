# 微光畅行 最终定稿完整版技术栈

## 1. 文档定位

本文档用于统一微光畅行项目的最终技术栈口径，作为后续功能开发、答辩表述、版本规划、兼容性设计和模块扩展的统一依据。

当前工程已确认的基础构建参数包括：

- 开发语言：`Kotlin`
- Android Gradle Plugin：`8.2.0`
- Gradle：`8.2`
- 最低兼容：`minSdk 21`
- 编译版本：`compileSdk 34`
- 目标版本：`targetSdk 34`

说明：

- 本文档中的内容分为“当前已确认基础能力”和“最终定稿目标技术选型”两部分。
- 若当前仓库中某些三方依赖尚未全部接入，以本文档作为后续实现基线，不影响答辩、方案归档和下一阶段开发设计。

## 2. 基础环境配置

- 开发语言：`Kotlin`
- 开发工具：`IntelliJ IDEA（Android 插件）`
- 构建版本：
  - Android Gradle Plugin：`8.2.0`
  - 本地 Gradle：`8.2`
- 版本适配：
  - 最低兼容：`minSdk = 21（Android 5.0）`
  - 编译版本：`compileSdk = 34`
  - 目标运行：`targetSdk = 34`
- 架构方案：模块化整洁架构 + `MVVM`
- 异步调度：`Kotlin Coroutines + Flow`

技术目标：

- 以 Android 5.0 作为最低可用底线，最大化覆盖老旧机型。
- 在不破坏核心模块的前提下支持新增功能独立接入。
- 保持业务层、数据层、设备适配层职责清晰，降低后续多模块并行开发成本。

## 3. 全局双层适配体系

### 3.1 系统版本适配

以 `API 21` 作为最低底线，代码内部统一做版本判断与能力降级。

- `Android 5.0 ~ 7.0`：
  - 启用基础功能闭环。
  - 对高版本专属 API 做降级替代。
  - 优先保证能运行、能提醒、能展示。
- `Android 8.0` 及以上：
  - 启用更完整的前台服务能力。
  - 启用精细震动控制与更完整的后台监听。
  - 启用更高阶的灯效、通知联动和细粒度系统能力。

### 3.2 全品牌硬件自适应

面向华为、小米、OPPO、vivo、魅族、荣耀等主流 Android 品牌做硬件差异适配。

自动识别内容：

- 屏幕尺寸与分辨率
- 线性马达或普通马达
- 闪光灯位置
- 背屏、呼吸灯、侧边灯
- 不同 ROM 的能力差异

自适应策略：

- 自动调整 UI 布局与控件密度
- 按硬件能力切换震动档位
- 根据设备能力切换提醒方式
- 根据设备支持情况切换灯效样式

### 3.3 权限管理

统一兼容老权限机制与高版本动态权限模型，按功能模块集中治理。

统一纳管权限包括：

- 相机
- 麦克风
- 悬浮窗
- 通知监听
- 后台运行
- 音量控制相关能力

目标是形成一套可复用的权限申请、回收、失败兜底与引导说明流程，避免后续各模块重复实现。

## 4. 数据存储方案

- 轻量配置：`DataStore`
- 低版本兜底：`SharedPreferences`
- 本地数据库：`Jetpack Room`

本地数据库承载内容：

- 预制热门药品库
- 双向手语词库
- 多天离线天气
- 用户设备适配偏好
- 用户个性化提醒配置

数据库兼容策略：

- 保证 `minSdk 21` 可稳定运行
- 支持从 `assets` 导入预制模板数据库
- 对表结构变更和首装导入过程做好兼容控制
- 避免因首版离线库初始化造成的闪退与字段缺失问题

## 5. UI 界面层

- 主力界面：`Jetpack Compose`
- 低端老旧机型兜底：原生 `XML`
- 页面路由：`Jetpack Navigation`

界面设计原则：

- 自适应流式布局，自动适配大小屏
- 保证核心信息在弱视和老旧设备上依然清晰可读
- 在复杂动画与低配流畅度之间优先保证稳定性

适配逻辑：

- 参考网页式响应布局思路
- 自动根据屏幕尺寸调整字体、控件大小和排版方式
- 必要时为低性能设备降级动画和特效

## 6. 全项目核心功能技术选型

### 6.1 双向手语互通

- 语音转文字：原生 `SpeechRecognizer`
- 手势识别：`MediaPipe Hands` 轻量兼容版
- 手语画面展示：`Lottie`
- 文字语音播报：系统原生 `TTS`

兼容策略：

- 低版本设备自动简化动画帧率
- 优先保证高频手语表达可演示、可理解、可扩展

### 6.2 高精准环境音聆听

- 音频采集：原生 `AudioRecord`
- 人声识别：轻量化 `TFLite` 离线人声模型
- 后台驻留：兼容版前台服务
- 触发联动：震动 + 闪光灯 + 屏幕提醒

设计目标：

- 在不依赖持续联网的前提下，尽量实现环境声事件捕获
- 对低配机保持持续监听可用性

### 6.3 全局消息超强强制提醒

- 通知抓取：`NotificationListenerService`
- 音量控制：`AudioManager`
- 三重提醒组合：
  - 自适应马达震动
  - 铃声最大化
  - 灯光闪烁

说明：

- 对静音、低音量、易漏看通知等场景进行强化补偿
- 不同系统版本与 ROM 上需做好权限失败兜底和用户引导

### 6.4 全机型自定义消息流光色效

- 无品牌专属灯效机型：悬浮窗自主绘制彩色边屏灯效
- 有原生灯效机型：优先调用系统接口
- 支持能力：
  - 自定义颜色
  - 自定义闪烁频率
  - 自定义显示时长

### 6.5 视障专属周期天气提醒

- 网络请求：`Retrofit + OkHttp`
- 定时任务：`WorkManager`
- 提醒策略：
  - 凌晨 6 点
  - 早上 8 点
  - 早上 9 点
  - 支持整点循环播报

增强策略：

- 恶劣天气优先高频推送
- 结合 `TTS` 语音播报与专属震动提醒

### 6.6 药品离线智能识别

- 相机框架：`CameraX`
- 文字识别：`ML Kit` 精简离线 OCR
- 数据匹配：本地 `Room` 预制药品数据库

目标是形成“拍照识别 -> 文本提取 -> 药品匹配 -> 风险提示 -> 语音播报”的离线优先闭环。

### 6.7 线性马达分级震动管理

- `API 26` 及以上：启用线性马达精细自定义震动节奏
- `API 21 ~ 25`：自动降级为标准简易震动模式

内置震动方案：

- 叫醒提醒
- 天气提醒
- 紧急预警

## 7. 通用辅助依赖组件

- 权限框架：`Accompanist Permissions`
- 图片加载：`Coil`
- 日志工具：`Timber`
- 稳定性保障：全局统一异常捕获

稳定性目标：

- 减少低端机型因权限、资源和组件初始化失败导致的崩溃
- 在功能降级时保持核心能力可继续使用

## 8. 打包发布流程

- 开发打包全程在 `IntelliJ IDEA` 内完成
- 调试安装包：

```bash
gradlew assembleDebug
```

- 正式发布包：

```bash
gradlew assembleRelease
```

发布优化项：

- 开启代码混淆
- 开启资源压缩
- 控制包体积
- 面向低配安卓机保持流畅运行

## 10. 整体总结

微光畅行最终采用 `AGP 8.2.0 + Gradle 8.2 + Kotlin` 作为稳定构建基础，最低下探 `Android 5.0（API 21）`，同时通过系统版本适配与硬件能力自适应实现对主流 Android 机型的大范围覆盖。

在此基础上，项目将围绕手语互通、环境音聆听、全局强提醒、天气播报、药品离线识别、线性马达分级震动等核心场景形成统一技术底座，确保：

- 首版可演示
- 低版本可运行
- 后续模块可扩展
- 多品牌设备可兼容
- 答辩口径与工程方向保持一致

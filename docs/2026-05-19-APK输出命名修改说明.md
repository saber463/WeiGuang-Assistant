# 2026-05-19 APK 输出命名修改说明

## 1. 变更目标

- 将应用模块生成的 APK 文件名统一修改为：

```text
微光畅行v1.01.apk
```

- 这样做的目的，是让测试包、演示包和交付包在文件管理器中更容易识别，避免继续使用默认的 `app-release.apk` 或类似名称。

## 2. 修改位置

- 文件：`app/build.gradle`

## 3. 修改内容

- 在 `android {}` 配置块中新增 APK 输出命名逻辑：

```groovy
applicationVariants.all { variant ->
    variant.outputs.all {
        outputFileName = "微光畅行v1.01.apk"
    }
}
```

## 4. 当前效果

- 执行 `release` 构建后，输出文件名已变为：

```text
app/build/outputs/apk/release/微光畅行v1.01.apk
```

## 5. 验证结果

- 已执行以下命令验证通过：

```bash
.\gradlew.bat :app:assembleRelease
```

- 构建结果：
  - `BUILD SUCCESSFUL`
  - 产物文件名已成功修改为 `微光畅行v1.01.apk`

## 6. 注意事项

- 当前写法会把当前 APK 输出统一命名为同一个文件名。
- 如果后续你同时需要区分：
  - `debug`
  - `release`
  - `signed`
  - `渠道包`
- 建议后续把命名规则升级为包含以下信息：
  - 应用名
  - 版本号
  - 构建类型
  - 日期

## 7. 后续建议

- 如果你接下来准备频繁打包，我建议下一步把命名规则改成自动版本化，例如：

```text
微光畅行-v1.01-release.apk
微光畅行-v1.01-debug.apk
微光畅行-v1.01-20260519.apk
```

- 这样后面多轮测试时，不容易被新包覆盖旧包，也方便回溯。

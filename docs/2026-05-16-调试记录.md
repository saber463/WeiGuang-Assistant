## 1. 本轮调试目标

确认微光畅行 Android 端药品离线库链路是否真正跑通，重点检查：

- `assets/db/drugs.db` 是否已经生成
- App 启动时是否实际加载该离线库
- 本地数据库是否仍只依赖代码种子数据
- 修改后是否还能正常构建

## 2. 调试发现

本轮调试定位到一个关键问题：

- `app/src/main/assets/db/drugs.db` 已经存在
- `CSV -> SQLite` 脚本也能正常生成数据库
- 但 App 运行时的 `DrugDatabaseProvider` 仍只使用 `Room.databaseBuilder(...)`
- 这意味着运行时并没有真正优先读取 `assets/db/drugs.db`

换句话说：

- 库文件有了
- 页面也能查数据
- 但实际还是在用 Kotlin 代码里的种子数据兜底

这不符合最终离线库接入目标。

## 3. 本轮修复

已在 `DrugDatabaseProvider` 中补上：

```kotlin
.createFromAsset("db/drugs.db")
```

当前实际策略变为：

1. 优先从 `assets/db/drugs.db` 创建本地数据库
2. 启动后执行 `ensureSeedData()`
3. 只有在数据库仍为空时，才补写代码种子数据

## 4. 修复后的意义

- CSV 生成出来的 SQLite 已经能真正进入 App 运行链路
- 后续扩充药品样本时，主要维护 CSV 即可
- 代码种子数据保留为兜底，不再是主数据来源

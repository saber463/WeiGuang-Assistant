## Bug #1 — Lottie 动画 JSON 文件缺失

### 严重程度
🔴 **阻塞** — 应用崩溃、手语动画完全无法播放

### 发现时间
2026-05-20（功能测试阶段）

### 文件位置
原始代码：`feature/signlanguage/LottieAnimationPlayer.kt`  
修复文件：
- [HandGestureView.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/core/animation/HandGestureView.kt)（新增）
- [LottieAnimationPlayer.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/feature/signlanguage/LottieAnimationPlayer.kt)（重写）

### 错误现象
```kotlin
// 原始代码尝试加载 assets/ 目录下的 Lottie JSON 文件
LottieCompositionFactory.fromAsset(context, "gesture_${gestureName}.json")
// 但这些 JSON 文件从来不存在于 assets/ 目录中
```

运行时崩溃：`FileNotFoundException: gesture_hello.json not found in assets`

### 根因分析
1. 项目依赖了 `com.airbnb.android:lottie:6.1.0` 库
2. 代码硬编码加载 `assets/` 下的 JSON 动画文件
3. **但这些动画文件从未被创建或下载**
4. Lottie JSON 文件是商业动画文件，需要设计师制作或从 LottieFiles 下载

### 解决方案

**方案：移除 Lottie 依赖，改为纯 Canvas 手绘动画**

步骤一：创建手形绘制引擎

```kotlin
// core/animation/HandGestureView.kt

    // Canvas 绘制 5 根手指关节 + 手掌 + 拇指

    // ValueAnimator 400ms 平滑过渡
    
    fun setGesture(name: String, animate: Boolean = true) {
        // 查表找 pose → 动画过渡 → invalidate()
    }
    
    override fun onDraw(canvas: Canvas) {
        // 用 drawCircle() 绘制关节 + drawLine() 绘制骨骼
    }
}
```

步骤二：从 [build.gradle](file:///f:/java/weiguangplus/app/build.gradle) 移除 Lottie 依赖
```gradle
// 移除
// implementation 'com.airbnb.android:lottie:6.1.0'
```

步骤三：重写播放器映射逻辑
```kotlin
// 将原来 pathToLottieAsset 改为 pathToGesture 映射
// 如 "water" → "open_palm"，"drink" → "thumb_up" 等 90+ 映射
```

### 影响范围
- 包体积减少约 **2MB**
- 用户不再需要下载额外的动画资源
- 首次安装即可使用手势动画

## Bug #2 — `weight` 导入权限不足

### 严重程度
🔴 **阻塞** — 编译失败

### 发现时间
2026-05-20

### 文件
[DualSignScreen.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/feature/signlanguage/DualSignScreen.kt)

### 错误现象
```
import androidx.compose.foundation.layout.weight  // Error
// This declaration is internal in Compose 1.5.2
// Cannot access 'weight': it is internal in 'ColumnScope'
```

### 根因分析
- `weight` 修饰符在 Compose 1.5.2 中是 `ColumnScope` 的扩展函数
- **不需要显式 import**，在 `Column` 的 content 作用域内自动可用
- 错误的导入方式导致编译器认为访问了 internal API

### 解决方案
```kotlin
// 错误：显式导入
import androidx.compose.foundation.layout.weight

// 正确：删除该导入，weight 在 ColumnScope 内可直接使用
Column {
    Button(modifier = Modifier.weight(1f)) { ... }  // 编译通过
}
```

## Bug #5 — `TopAppBar` Experimental API 未标注

### 严重程度
🟡 **中等** — 编译警告（可运行但有 warning）

### 发现时间
2026-05-20

### 文件
所有使用 Material3 `TopAppBar`、`FilterChip`、`ExposedDropdownMenu` 等的 Compose 文件

### 错误现象
```
'TopAppBar(..., navigationIcon: ...)' is an experimental Material3 API.
This function is experimental and is likely to change in the future.
```

### 根因分析
- Material3 的许多 API 在 1.1.x/1.2.x 版本中标记为 `@ExperimentalMaterial3Api`
- Compose 编译期要求开发者显式接受实验性 API 的使用

### 解决方案

**方式一（推荐）：在函数上标注**
```kotlin
@OptIn(ExperimentalMaterial3Api::class)
@Composable
fun MyScreen() { ... }
```

**方式二（全局）：在文件的 package 声明前加**
```kotlin
@file:OptIn(ExperimentalMaterial3Api::class)
package com.weiguangchangxing.weiguang_plus.feature.xxx
```

### 影响文件
`LearningCenterScreen.kt`、`FacilityReportScreen.kt`、`ServiceBookingScreen.kt`、`MainActivity.kt` 等 8 个文件

## Bug #6 — CameraX `findComponentActivity()` 空安全

### 严重程度
🟡 **中等** — 编译警告，潜在运行时 NPE

### 发现时间
2026-05-20

### 文件
[SignScreen.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/feature/signlanguage/SignScreen.kt)  
[DualSignScreen.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/feature/signlanguage/DualSignScreen.kt)  
[VisionScreen.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/feature/vision/VisionScreen.kt)  
[CameraObjectRecognizer.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/feature/vision/CameraObjectRecognizer.kt)

### 错误现象
```kotlin
val activity = context.findComponentActivity()
// findComponentActivity() 返回 ComponentActivity? (可空类型)
activity.cameraProviderFuture.addListener(...)
// 未判空直接调用，如果 activity == null 则 NPE
```

### 根因分析
- `LocalContext.current.findComponentActivity()` 是 Compose 中获取当前 Activity 的方式
- 返回类型是 `ComponentActivity?`（可为 null）
- 在非 Activity 上下文中调用时会返回 null

### 解决方案
```kotlin
val activity = context.findComponentActivity() ?: return
// 或者
activity?.let { act ->
    val cameraProviderFuture = ProcessCameraProvider.getInstance(act)
    cameraProviderFuture.addListener({ ... }, ContextCompat.getMainExecutor(act))
}
```

## Bug #7 — `cos()` / `sin()` 类型不匹配

### 严重程度
🔴 **阻塞** — 编译失败

### 发现时间
2026-05-20

### 文件
[HandGestureView.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/core/animation/HandGestureView.kt)

### 错误现象
```
Type mismatch: inferred type is Double but Float was expected
// 发生在 cos() / sin() 的返回值上
```

### 根因分析
- `kotlin.math.cos()` 和 `kotlin.math.sin()` 接受 `Double` 参数，返回 `Double`
- 但 `HandGestureView` 中的坐标计算使用的是 `Float` 类型
- Kotlin 不做隐式数字类型转换

### 解决方案
```kotlin
// 错误：直接使用
val x = centerX + length * cos(angle)  // cos 返回 Double，与 Float 不兼容

// 正确：显式转换
val x = centerX + length * cos(angle).toFloat()
val y = centerY + length * sin(angle).toFloat()

// 或者：使用 Float 版本的 cos/sin
import kotlin.math.cos
val x = centerX + length * cos(angle).toFloat()
```

## Bug #8 — R8 混淆 Missing class `javax.lang.model`

### 严重程度
🔴 **阻塞** — Release 构建失败

### 发现时间
2026-05-20

### 文件
[proguard-rules.pro](file:///f:/java/weiguangplus/app/proguard-rules.pro)（修复）

### 错误现象
```
Missing classes detected while running R8
Missing class javax.lang.model.SourceVersion
Missing class javax.lang.model.element.Element
Missing class javax.lang.model.element.ElementKind
...
```

### 根因分析
- MediaPipe SDK 内部嵌入了 **AutoValue**（代码生成器）+ **JavaPoet**（Java 代码生成库）
- 这些库在编译期引用 `javax.lang.model.*`（JDK 编译工具类）
- Debug 构建不启用 R8 混淆，所以没问题
- Release 构建启用 `minifyEnabled true`，R8 扫描所有引用链，发现这些类不在 classpath 中，报 Missing class 错误
- **这些类只在编译期需要，运行时不需要**

### 解决方案
在 [proguard-rules.pro](file:///f:/java/weiguangplus/app/proguard-rules.pro) 中添加：

```proguard
# AutoValue / JavaPoet - MediaPipe 依赖的编译期类
-dontwarn autovalue.shaded.com.squareup.javapoet.**
-dontwarn com.google.auto.value.**
-dontwarn javax.lang.model.**
-dontwarn autovalue.shaded.**
-keep class autovalue.shaded.** { *; }
```

### 作用说明
| 规则 | 作用 |
|------|------|
| `-dontwarn` | 阻止 R8 输出 Missing class 警告/错误 |
| `-keep class autovalue.shaded.**` | 保留已被重新打包（shaded）的 AutoValue 类，防止被混淆移除 |

### 严重程度
🟡 **中等** — 编译失败

### 发现时间
2026-05-20（批量创建功能文件时）

### 文件
[BusMetroScreen.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/feature/transportation/BusMetroScreen.kt)  
[AccessibleMapScreen.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/feature/map/AccessibleMapScreen.kt)

### 错误现象
```kotlin

import com.weiguangchangxing.weiguang_plus.core.service.BusStopMonitor.BusStop
// 报错：BusStop 是顶层类，不是 BusStopMonitor 的内部类
```

- 这是 AI 代码生成代理的上下文理解偏差

### 解决方案

```kotlin
import com.weiguangchangxing.weiguang_plus.core.service.BusStopMonitor.BusStop

import com.weiguangchangxing.weiguang_plus.core.service.BusStop
import com.weiguangchangxing.weiguang_plus.core.service.BusLine
import com.weiguangchangxing.weiguang_plus.core.map.AccessibleLocation
```

## Bug #10 — Kotlin 不支持 `_` 作为函数参数名

### 严重程度
🟡 **中等** — 编译失败

### 发现时间
2026-05-20

### 文件
[TripleAlertSystem.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/feature/notification/TripleAlertSystem.kt)

### 错误现象
```kotlin
private fun getVibrationAmplitudes(level: AlertLevel, _: Int): IntArray {
    // Error: Name expected
    // Kotlin does not support underscore-only parameter names in function declarations
}
```

### 根因分析
- **Kotlin 不支持** `_` 作为具名函数的参数名（Lambda 表达式参数支持 `_`）
- 修复代理错误地将 `size` 改为 `_` 以期抑制未使用参数警告
- 正确的做法是保留参数名 + `@Suppress("UNUSED_PARAMETER")`

### 解决方案
```kotlin
// 错误：Kotlin 不支持
private fun getVibrationAmplitudes(level: AlertLevel, _: Int): IntArray { ... }

// 正确：保留参数名 + 抑制警告
@Suppress("UNUSED_PARAMETER")
private fun getVibrationAmplitudes(level: AlertLevel, patternSize: Int): IntArray { ... }
```

## Bug #13 — 不必要空安全调用警告

### 严重程度
🟢 **轻微** — 编译警告

### 数量
**5 处**

### 文件
[MainActivity.kt](file:///f:/java/weiguangplus/app/src/main/java/com/weiguangchangxing/weiguang_plus/MainActivity.kt)

### 错误现象
```kotlin
// 让 Vibrator 变量声明为非空，但调用时仍然使用 ?. 安全调用
// 触发 Unnecessary safe call on a non-null receiver of type Vibrator
vibrator?.hasVibrator()          // 警告
vibrator?.vibrate(...)           // 警告
vibrator?.hasAmplitudeControl()  // 警告
vibrator?.cancel()               // 警告
```

### 根因分析
- 代码中 `vibrator` 变量声明为 `Vibrator`（非空）而非 `Vibrator?`
- 变量来源经过了 null 判断，编译器已确定为非空
- 但仍然使用了 `?.` 安全调用运算符，属于冗余调用

### 解决方案
```kotlin
// 错误：变量已是非空，无需安全调用
vibrator?.vibrate(...)

// 正确：直接调用
vibrator.vibrate(...)
```

# 2026-05-16 Android 数据库接入说明

> 口径说明：本文档保留用于说明 Android 端数据库接入过程，但不再作为药品离线库结构与维护流程的正式基线。
> 当前唯一正式基线文档为：`docs/2026-05-19-药品离线库正式基线说明.md`。
> 当前结构权威以 `Room / AppDatabase` 为准，CSV、SQL 和构建脚本必须跟随正式基线同步。

## 1. 本次目标

将微光畅行 Android 端从“只有 Room 骨架”推进到“本地数据库真正可运行”的状态，保证药品模块可以在无网条件下完成本地查询演示，并联动手语映射和风险提示。

## 2. 本次完成内容

### 2.1 数据库真正实例化

- 新增 `DrugDatabaseProvider`
- 采用 `Room.databaseBuilder()` 创建本地数据库 `weiguang_drugs.db`
- 当前使用单例模式提供数据库和 Repository

文件：

- `app/src/main/java/com/weiguangchangxing/weiguang_plus/data/local/DrugDatabaseProvider.kt`

### 2.2 首次启动自动写入种子数据

当前采用“`assets/db/drugs.db` 优先加载 + 代码种子兜底”的方式：

- App 首次启动优先从 `assets/db/drugs.db` 创建本地数据库
- 若本地数据库为空，则自动写入首版演示种子数据
- 种子数据覆盖：
  - 药品主表
  - 药品详情表

- 已生成的正式离线库
- 早期调试环境
- 资源缺失时的运行兜底
- 种子数据覆盖：
  - 药品主表
  - 药品详情表
  - 药品别名表
  - 药品手语映射表
  - 风险规则表
  - 默认用户档案

当前内置的演示药品：

- 布洛芬缓释胶囊
- 阿莫西林胶囊
- 盐酸二甲双胍片

### 2.3 手语映射已接入数据库层

新增表对应实体：

- `DrugSignMappingEntity`

当前支持字段：

- `sign_keyword`
- `sign_display_text`
- `video_path`
- `image_seq_path`
- `spelling_mode`

这意味着药品查询结果已经可以直接带出“对应手语演示资源”的占位信息。

### 2.4 药品页已接通真实本地查询

`MedicineScreen` 不再是纯静态页面，而是已经接到本地 `Repository`：

- 支持输入药名、别名或 OCR 结果关键词
- 支持查询本地 Room 数据库
- 支持显示结构化药品信息
- 支持显示手语联动结果
- 支持根据命中结果生成风险播报文案

## 3. 当前实现方式

### 3.1 当前链路

```text
MedicineScreen
-> DrugRepository
-> LocalDrugRepository
-> Room DAO
-> SQLite (weiguang_drugs.db)
```

### 3.2 App 启动时的处理

```text
MainActivity / WeiguangPlusApp
-> 获取 DrugRepository
-> 调用 ensureSeedData()
-> 若数据库为空则写入首版样本
```

## 4. 当前调试结论

调试中已确认并修复一个关键问题：

- 之前 `assets/db/drugs.db` 虽然已经生成，但 App 运行时并没有实际加载它
- 当前已修复为优先使用 `assets/db/drugs.db`
- 代码种子数据现在只保留为兜底逻辑

这种方式的好处是：

- 比赛演示更贴近最终离线库方案
- CSV -> SQLite 的结果可以直接进入 App
- 即使离线库临时缺失，应用仍不会完全空白

## 5. 下一步如何继续强化

当前已经切到 `assets/db/drugs.db` 优先模式，下一步建议如下：

4. 后续再视需要补数据库版本升级策略

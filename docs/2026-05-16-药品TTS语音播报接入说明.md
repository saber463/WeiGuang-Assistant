# 2026-05-16 药品 TTS 语音播报接入说明

## 1. 文档目标

这份文档用于说明微光畅行药品模块本轮新增的 `TTS 语音播报` 能力。

本轮完成后，药品模块已经具备三通道提醒能力：

- 文字结果
- 震动提醒
- 语音播报

这样做的目标是让听障、低视力、老年用户在药品风险结果出现时，能通过多种通道同时接收到提醒信息。

## 2. 当前接入方式

### 2.1 使用系统 TTS

当前版本直接使用 Android 系统 `TextToSpeech` 能力，不额外引入第三方语音 SDK。

优点：

- 接入快
- 依赖轻
- 适合 4 天首版交付
- 不新增明显版权风险

### 2.2 生命周期管理

当前在药品页内部完成 TTS 引擎初始化，并在页面释放时执行：

- `stop()`
- `shutdown()`

这样做是为了避免：

- 重复初始化
- 页面切换后语音资源泄漏
- 多次进入页面后播报异常

## 3. 当前播报触发逻辑

### 3.1 自动播报时机

当前只在 `用户主动触发查询` 时自动播报，包含：

- 点击 `查询本地库`
- 点击 `恢复示例`
- 点击 `使用这条 OCR 结果查询`
- 点击 `把当前输入当作 OCR 结果接入`

### 3.2 为什么不在页面首次进入时自动播报

这是出于安全和体验考虑：

- 避免用户刚进入页面就被突然打断
- 避免还没看清结果就自动开始读
- 避免在比赛演示或用户访谈时显得过于嘈杂

因此当前策略是：

- 首次进入页面只初始化 TTS
- 用户主动查询后再自动播报

## 4. 当前播报内容

当前播报内容来自药品页已有的风险播报文案，包含：

- 当前来源
- 识别到的药品名称
- 重点查看信息
- 风险提示
- 人工复核提醒

### 4.1 风险级别前缀

为防止用户把高风险结果听成普通说明，当前会在语音播报前自动添加前缀：

- `high`：高风险提醒
- `medium`：重点核对提醒
- `low / null`：不额外添加风险前缀

## 5. 当前页面表现

当前药品页已新增：

- `语音播报反馈` 模块
- `立即重播风险语音` 按钮

这样用户和评委可以清楚看到：

- 当前语音是否初始化成功
- 本次是否已经自动播报
- 若失败，失败后的降级策略是什么

## 6. 降级策略

如果 TTS 当前不可用，页面不会中断主流程，而是自动退回到：

- 文字展示
- 风险卡片
- 震动提醒

也就是说，TTS 是增强能力，不是唯一能力。

## 7. 为什么这个方案适合当前版本

### 7.1 安全边界更清晰

TTS 播报的是辅助判断结果，不会替代医生和正式说明书。

### 7.2 无障碍价值更直接

对低视力用户、老年用户和陪护人员来说，语音播报能明显降低阅读门槛。

### 7.3 技术风险低

当前没有引入新版权风险，也没有引入云端依赖，适合离线 MVP 演示。

## 8. 当前边界

当前版本仍然有这些限制：

- 还没有做语速、音量、音色的自定义设置
- 还没有接入高风险重复播报策略
- 还没有做播报中断队列管理
- 还没有做多语言支持

## 9. 建议下一步

最推荐继续推进的 3 件事：

1. 高风险命中时增加重复播报或二次确认
2. 增加播报开关、语速调节和音量建议
3. 后续把 OCR 实时识别结果和 TTS 自动播报进一步打通

## 一、背景与目标

G1 将"环境音监控"从"检测到声音"升级为"识别是什么声音"，对听障用户实现**多模态声音感知**。

### 1.1 现实约束（关键决策）

待开发文档建议基于 Google Audio Set 预训练模型微调来实现**通用声音分类**（门铃/警报/电话/婴儿哭等）。但：
- 项目 `assets/` 中**没有**现成的 TFLite 音频分类模型文件
- 通用声音分类模型无法通过代码凭空生成，需要待后续引入（如 YAMNet，约 14MB 模型文件）

因此本次先实现 **G1 基础框架**：**不依赖外部模型、可独立编译运行、具备真实价值**的部分，将 `AmbientSoundMonitor` 从 TODO 占位升级为完整实现。

### 1.2 本次交付范围

1. **音频采集**：`AudioRecord` 持续采集麦克风 16kHz 单声道 PCM
2. **特征提取**：分帧计算时域特征（RMS 能量 + 过零率 ZCR），无外部依赖
3. **自定义声音训练**：用户录制 3s 样本 → 提取特征 → 保存到本地文件 → 余弦相似度匹配
4. **多模态提醒**：检测到已训练声音触发 振动 + 闪光灯 双通道提醒

后续接入通用分类模型时，仅需替换/扩展特征提取输入（改为 MFCC 谱特征），分类匹配框架保持不变。

### 1.3 存储方案

自定义声音样本（名称 + 特征向量）使用 **本地 JSON 文件**（`context.filesDir`）持久化，**不新增 Room 实体、不触发数据库版本迁移**，降低重构风险。样本量小（每样本约几十个浮点数），JSON 足够。

## 三、核心逻辑设计

### 3.1 特征提取（CustomSoundTrainer）
```
16kHz 音频 → 每帧 2048 样本(128ms) → RMS 能量 + 过零率
→ 连续 N 帧合成一个特征向量（RMS 均值/ZCR 均值 + 能量轮廓）
```

### 3.2 匹配算法
- **余弦相似度**：特征向量逐候选比对，相似度最高且 > 阈值(0.85) 判定命中
- **滑动确认**：连续 `consecutiveHits` 帧（默认 3 帧≈0.4s）均命中同一标签才触发提醒，避免瞬时误报

### 3.3 多模态提醒（SoundAlertManager）
```
命中 → 去抖(8s 防重复) → VibrationController.vibratePattern(CUSTOM) + FlashlightController.blink()
```

# 2026-05-16 高风险联动提醒说明

## 1. 文档目标

这份文档用于说明微光畅行药品模块本轮新增的“高风险联动提醒”能力。

本轮不是只做风险文字展示，而是把风险结果继续向前推进到：

- 页面警示
- 状态反馈
- 震动提醒

这样做的目标是让听障用户、低视力用户和比赛评委都能更直观地感知高风险结果。

## 2. 当前联动逻辑

当前药品页在用户点击查询后，会按以下顺序执行：

```text
输入药名 / 别名 / OCR 结果
-> 本地 SQLite 检索
-> 聚合药品详情和风险规则
-> 计算最高风险级别
-> 生成风险播报文案
-> 根据风险级别决定是否触发震动提醒
-> 在页面显示风险联动反馈
```

## 3. 当前风险级别与动作映射

### 3.1 高风险

触发动作：

- 页面显示高风险人工复核卡片
- 触发强震动提醒
- 风险联动反馈明确提示“立即停止自行判断并转人工复核”

适用含义：

- 禁忌命中
- 高危过敏史
- 需要优先转医生 / 药师复核的情况

### 3.2 中风险

触发动作：

- 页面显示中风险重点复核卡片
- 触发中等强度震动提醒
- 风险联动反馈提示继续结合病史与说明书核对

适用含义：

- 慎用
- 重点监测
- 慢病人群需谨慎核对

### 3.3 低风险

触发动作：

- 页面继续保留风险卡片
- 不触发强震动
- 页面提示继续人工核对

### 3.4 未命中风险

触发动作：

- 不触发震动
- 页面保留一般提醒

## 4. 当前实现方式

### 4.1 查询入口

当前在药品页点击以下动作时会主动触发风险联动判断：

- `查询本地库`
- `恢复示例`

### 4.2 震动策略

当前复用已有的设备振动能力，按风险级别映射为不同波形：

- `high`：更强、更连续的波形
- `medium`：中等强度波形
- `low / null`：不触发额外震动

### 4.3 页面反馈

新增“风险联动反馈”模块，用来明确展示：

- 本次是否触发了风险提醒
- 当前触发的是哪一类动作
- 为什么触发或没有触发

## 5. 为什么这样设计

### 5.1 用户安全优先

如果只显示一段风险文字，用户很容易忽略。

而联动提醒可以把高风险结果从“看见”提升到“感知到”。

### 5.2 无障碍场景更需要多通道提醒

针对不同用户，风险提醒应至少具备：

- 视觉：高对比度卡片
- 文字：明确动作建议
- 触觉：震动反馈

### 5.3 比赛展示更直观

评委在短时间内更容易理解：

- 系统不是只会查药名
- 系统会按风险级别做不同处理

## 6. 当前限制

本轮实现仍有这些边界：

- 当前震动提醒只在手动查询后触发
- 还没有与 OCR 自动识别结果自动联动
- 还没有与 TTS 联动成完整的“高风险语音警报”
- 还没有做真机级别的品牌差异分层

## 7. 下一步建议

最推荐继续推进的 3 件事：

1. 把 OCR 识别结果直接接入高风险联动提醒
2. 高风险命中时同步触发语音提醒
3. 针对不同机型进一步细化震动强度与节奏

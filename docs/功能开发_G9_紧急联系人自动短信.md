## 一、背景与目标

当 G1 声音事件分类检测到**紧急声音事件**（火灾警报、烟雾警报）时，听障用户在紧急情况下可能无法主动触发 SOS。G9 让系统**自动**向预设紧急联系人发送短信通知（含事件类型 + GPS 位置），并支持自动拨打急救电话。

**核心价值**：补全安全闭环 —— "系统感知到危声音 → 自动求助"。

## 二、设计决策

### 2.1 与 SosManager 的关系（关键）
不复用 `SosManager.trigger()` 的完整流程，因为：
- `trigger()` 内部会触发**震动 + TTS 播报 + 闪光灯 SOS 摩斯码**，那是**用户主动求救**的全套警示流程
- G9 是**系统自动**检测告警，不需要用户主动场景的强烈警示，只需**静默发短信**通知

因此 `AutoEmergencyNotifier` 独立实现：
- 复用 `EmergencyContactManager`（已配置的紧急联系人数据）
- 复用与 `SosManager` 相同的 **GPS 获取 + SmsManager 发送** 逻辑（避免触碰 trigger 的复杂流程）

### 2.2 防误触机制
紧急声音需**连续确认 N 帧**才触发自动通知（参考 SOS 8 帧确认理念）：
- 由触发方（G1）负责连续确认后回调本协调器
- 协调器内部再做 **时间级去抖**（两次自动通知间隔 ≥ 60s），防止同一波告警重复轰炸

### 2.3 短信内容
在复用 SOS 模板基础上加入事件类型描述，让接收方能判断紧急性质。

## 三、实现

### 3.1 新增文件
`core/emergency/AutoEmergencyNotifier.kt`（object 单例）

### 3.2 核心 API
- `notifyEmergencyEvent(context, eventType, onResult)`：发送含事件类型的自动告警短信给全部紧急联系人（内含 GPS 定位 + 去抖 + 闪光灯警示）
- `canSendNow()`：是否已过去抖窗口（供 G1 判断是否值得触发）
- `resetDebounce()`：重置去抖（训练新样本/测试用）

### 3.3 涉及现有模块
- `EmergencyContactManager.getContacts()`：复用联系人
- `LocationManager + SmsManager`：复用 SosManager 相同逻辑
- `FlashlightController`：发送同时闪光警示（复用）

## 四、验证方式

1. `gradlew.bat :app:assembleDebug` 编译通过。
2. 真机：设置紧急联系人 → 手动调用 `notifyEmergencyEvent(context, "火灾警报")` → 接收方收到含事件类型的短信。
3. 60s 内重复触发被去抖抑制。

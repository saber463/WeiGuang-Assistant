# 2026-05-19 APK 打包失败修复说明

## 1. 问题现象

- 在 Android Studio / IDEA 中执行 `release` 相关构建时失败。
- 关键报错如下：

```text
> Task :app:kaptReleaseKotlin FAILED
MainActivityKt.java:132: 错误: 不兼容的类型: NonExistentClass无法转换为Annotation
    @error.NonExistentClass
```

- 表面看像是 `kapt` 或 `Room` 注解处理器异常，但这不是最初根因。

## 2. 根因分析

- `app/src/main/java/com/weiguangchangxing/weiguang_plus/MainActivity.kt` 同时导入了两个同名类型 `Preview`：
  - `androidx.camera.core.Preview`
  - `androidx.compose.ui.tooling.preview.Preview`
- 业务代码里：
  - CameraX 预览构建使用了 `Preview.Builder()`
  - Compose 预览函数使用了 `@Preview`
- 这两个符号在 Kotlin 源码层表面可读，但在 `kaptReleaseKotlin` 生成 Java stub 时，`@Preview` 注解解析失败，被降级成：

```text
@error.NonExistentClass
```

- 因为 KAPT 生成的 stub 已经损坏，后续注解处理阶段会继续抛出反射或处理器异常，从而误导排查方向。

## 3. 修复方案

- 对两个 `Preview` 做显式别名，彻底消除同名冲突：
  - `androidx.camera.core.Preview as CameraXPreview`
  - `androidx.compose.ui.tooling.preview.Preview as ComposePreview`
- 同步修改两个使用点：
  - CameraX 预览构建改为 `CameraXPreview.Builder()`
  - Compose 预览注解改为 `@ComposePreview(...)`

## 4. 修改文件

### 4.1 主修复文件

- 文件：`app/src/main/java/com/weiguangchangxing/weiguang_plus/MainActivity.kt`
- 修改内容：
  - 导入别名化，避免 `Preview` 名称冲突
  - CameraX 预览构建引用改名
  - Compose 预览注解引用改名

- 当前生成的 release 包位于：

```text
app/build/outputs/apk/release/app-release-unsigned.apk
```

- 说明：
  - 当前产物是 `unsigned`，表示已经完成 `release` 构建，但还没有做正式签名。
  - 如果需要安装测试或对外分发，还需要继续配置 keystore 并执行签名流程。

## 7. 后续建议

- 代码里尽量避免同时导入同名类或注解，尤其是：
  - `Preview`
  - `Surface`
  - `Text`
  - `Path`
  - `Color`
- 如果必须共存，优先使用 `as` 做别名。
- 遇到 `@error.NonExistentClass` 时，优先检查：
  - 注解是否真实存在
  - 导入是否冲突
  - 当前构建变体是否能拿到对应依赖
  - 是否是 `kapt` 生成 stub 阶段已损坏

## 8. 本次结论

- 这次 APK 打包失败的根因不是业务逻辑，也不是 Room 数据表定义错误。
- 真正原因是 `MainActivity.kt` 中 `Preview` 同名导入冲突，导致 `release` 阶段 KAPT 无法正确解析 Compose 预览注解。
- 通过显式别名化后，`release` 构建链路恢复正常。

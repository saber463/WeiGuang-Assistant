# 可行性调研：G5 说话人区分

> 调研日期：2026-08-21 | 时区：UTC+8 北京时间 | 类型：技术方案调研（未实现功能）
> 结论：**可行但需引入新的声纹模型**，属于"高成本 / 中契合度"方向，建议作为长期规划、非近期落地。

---

## 一、背景与现状

### 1.1 G5 需求
在通话转写 / 悬浮窗字幕 / 转录历史中，为每一句转录区分"是哪个说话人"（如"对方 / 我"，
或多人场景下的人 A / 人 B），让听障用户更清楚对话来源。

### 1.2 当前实现
- 通话转写：`core/call/CallTranscriber.kt` 走 **Android 系统 `SpeechRecognizer`**（在线）；
- 手语/字幕：`core/signlanguage/VoiceRecognizer.kt` 同为系统 `SpeechRecognizer`；
- `build.gradle.kts` 已依赖 `com.alphacephei:vosk-android:0.3.37`，但实际离线识别未启用。
- **结论：当前没有任何说话人（声纹）能力**，系统 `SpeechRecognizer` 不返回说话人身份信息。

## 二、技术原理

说话人区分（Speaker Recognition）核心含两步：
1. **声纹嵌入（Speaker Embedding）**：把一段语音映射为一个固定维度向量（如 d-vector / x-vector），
   相同说话人向量相近、不同说话人向量远离；
2. **判定/聚类**：新语音的嵌入与"注册库"中各说话人嵌入算 **余弦相似度**，超过阈值则归为该人；
   未注册情况用聚类判断说话人个数（Speaker Diarization）。

## 三、候选方案对比

| 方案 | 说明 | 契合度 | 风险/成本 | 结论 |
|------|------|:------:|-----------|:----:|
| **A. Vosk 说话人识别** | Vosk 的 `speaker` 识别为实验特性，Kotlin 端 API 支持弱，需专用 speaker 模型 | 中 | 高（模型支持不稳定、文档少、训练弱） | ❌ 不推荐 |
| **B. TFLite 声纹嵌入（推荐）** | 用开源声纹模型（ECAPA-TDNN / d-vector）导出 TFLite，本地提取嵌入 + 余弦打分 | 高 | 中（需模型文件 + 尺码校准） | ✅ 推荐 |
| **C. 系统/云端 API** | 云服务说话人 diarization（如各语音平台） | 低 | 依赖网络、违反本地隐私原则 | ❌ 与"本地推理"项目约束冲突 |

> 项目有端到端本地加密、语音本地处理定位，故优先本地推理方案（B），符合"不把用户语音上传"的既有隐私策略。

## 四、推荐方案（B）数据流设计与集成点

```
麦克风帧 → VAD 语音活性检测（切出有效语音段）
         → 声纹嵌入模型（TFLite d-vector 128/192 维）
         → 嵌入缓冲
             ├─ 注册阶段：录入"我是谁"→ 向量存 Room（SpeakerProfile）
             └─ 判定阶段：与注册库余弦相似度 → 超过阈值 TOP1 → 打上说话人标签
```

- **集成点**：在 `CallTranscriber` / `CaptionOverlayService` 的转写结果旁附加 `speakerLabel`；
- **存储**：独立 Room 库 `SpeakerProfile`（姓名 + 归一化嵌入向量 + 采样样本数）；
- **轻量 VAD**：可先以"RMS 能量阈值 + 静音停顿切分"实现（与 G10 的 RMS 逻辑同源），不引额外依赖。

## 五、可行性结论

- **功能可行**：说话人区分在工程技术上是成熟路线，移动端 TFLite 可承担推理；
- **需新增**：一个声纹嵌入模型（TFLite，约 CB-数 MB）+ 向量注册/余弦打分逻辑 + Room 存储；
- **契合度中**：mediapipe/TFLite 集成经验可复用，但需评估具体声纹模型在中文/短语音上的准确率与冷却注册体验。

### 直接风险
1. **短句准确率**：语段过短（<0.5s）时嵌入不稳定，需按语音段聚合再打分；
2. **冷启动**：首次使用需为各说话人注册样本，交互成本高于纯转写；
3. **实时性**：嵌入推理（约毫秒~几十毫秒/段）对字幕场景可接受，但需线程调度，避免卡顿主线程；
4. **模型合规**：声纹模型需确认可在项目本地离线分发（Apache/CC 类许可）。

## 六、分阶段落地建议（仅规划，未排期）

| 阶段 | 内容 | 工作 | 说明 |
|------|------|------|:----:|
| S1 | 声纹嵌入可行性 POC | 选取并导出 TFLite 模型，跑通"录音→嵌入→余弦"最小链路 | 低 |
| S2 | 注册与判定 | SpeakerProfile Room + 相似度打分 + 标签 | 中 |
| S3 | 接入转写/字幕 | 在转录旁附加说话人标签，UI 展示 | 中 |
| S4 | 多人说话人聚类 | 引入聚类判断未注册说话人个数 | 高（可延后） |

> 总体评估：**建议将其列为长期能力，优先排期较低收益比**；若后期需"谁在说"的硬需求，可先上 S1 POC 验证模型在真实设备上的准确率再决定投入。

## 附：参考资料要点
- Speaker Embedding：d-vector、x-vector、ECAPA-TDNN；
- 余弦相似度阈值校准需要在真实录音上标注曲线；
- 短视频法发(post-filtering)与语音段聚合可显著提升短句场景鲁棒性。

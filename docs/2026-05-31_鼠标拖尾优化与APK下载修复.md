## 一、鼠标拖尾频率优化

### 问题描述
鼠标移动时产生的emoji拖尾（👣☀️🌻🌸🌼🍃🌺）数量过多、频率过高，影响页面浏览体验。

### 原始参数
```javascript
// 原始代码（index.html 第1061行）
if (dist < 25 && now - lastTime < 60) return;
```
- 距离阈值：25px → 鼠标移动25像素就生成一个emoji
- 时间阈值：60ms → 每60毫秒就允许生成一个
- 实际效果：快速移动鼠标时，每秒可产生数十个emoji

### 优化后参数
```javascript
// 优化后代码
if (dist < 80 && now - lastTime < 200) return;
```
- 距离阈值：80px → 鼠标需移动80像素才生成
- 时间阈值：200ms → 至少间隔200毫秒
- 实际效果：emoji生成频率降低约 **6-7倍**，视觉上更舒适

### 修改文件
- `web/index.html` 第1054-1071行（Mouse Trail IIFE）

## 二、APK下载失败修复

### 问题描述
用户已将 `app-release.apk` 上传到宝塔面板服务器，但电脑浏览器点击"下载 APK"按钮时下载失败。

### 根本原因
宝塔面板默认使用 **Nginx** 作为Web服务器，而Nginx默认配置中 **没有 `.apk` 文件的MIME类型映射**。
- 桌面浏览器收到响应时，Content-Type 为 `application/octet-stream` 或 `text/html`
- 浏览器无法识别这是Android安装包，导致下载中断或直接在页面内显示乱码
- 手机浏览器通常能绕过此限制（因为手机有Android系统级处理）

### 修复方案

#### 方案A：宝塔面板Nginx配置（推荐）

1. 登录宝塔面板 → **网站** → 找到对应站点 → **设置**
2. 左侧菜单选择 **配置修改** 或 **Nginx配置**
3. 在 `server { }` 块内添加：

```nginx
# APK文件MIME类型配置
location ~* \.apk$ {
    add_header Content-Type "application/vnd.android.package-archive";
    add_header Content-Disposition "attachment";
}
```

4. 点击 **保存** → **重启Nginx**

#### 方案B：已创建的配置文件

项目中已创建以下文件，随网站一起部署到服务器即可：

| 文件 | 适用环境 | 说明 |
|------|----------|------|
| `.htaccess` | Apache | 自动识别apk MIME类型 + 强制下载 |
| `web.config` | IIS (Windows Server) | 同上 |

> 如果宝塔用的是Nginx，`.htaccess` 不会生效，必须用方案A修改Nginx配置。

### 修改文件
- 新建 `web/.htaccess` — Apache MIME类型配置
- 新建 `web/web.config` — IIS MIME类型配置

### 验证方法
修改完成后：
1. 打开浏览器访问 `https://你的域名/app-release.apk`
2. 应该直接触发下载，而不是在页面显示乱码
3. F12打开开发者工具 → Network → 点击下载按钮 → 检查响应头中 `Content-Type` 是否为 `application/vnd.android.package-archive`

## 三、注意事项

1. **APK文件路径**：下载链接 `href="app-release.apk"` 是相对路径，APK文件必须与 `index.html` 放在同一目录下
2. **文件名一致**：确保服务器上的文件名就是 `app-release.apk`，不要有中文或空格
3. **HTTPS证书**：如果网站使用HTTPS，确保SSL证书有效，否则部分浏览器会阻止APK下载
4. **防火墙**：宝塔面板的防火墙插件可能会拦截大文件下载，检查是否放行了80/443端口

# 2026-05-19 药品离线库正式基线说明

## 1. 文档目的

本文档是微光畅行药品离线库的唯一正式基线说明。

从今天开始，药品离线库链路统一执行以下原则：

- `Room / AppDatabase` 决定运行时结构
- `CSV` 决定可维护内容
- `tools/build_seed_db.py` 只负责把 `CSV` 按正式 schema 编译成 `drugs.db`
- 任何人都不允许手改 `app/src/main/assets/db/drugs.db`

如果历史文档、旧 SQL、旧 CSV 表头或旧脚本说明与本文档冲突，一律以本文档和当前代码中的 `Room Entity + AppDatabase` 为准。

## 2. 运行时结构权威

运行时数据库结构的唯一权威是：

- `app/src/main/java/com/weiguangchangxing/weiguang_plus/data/local/AppDatabase.kt`
- `app/src/main/java/com/weiguangchangxing/weiguang_plus/data/local/entity/`

这意味着：

- 表名以 `Room Entity` 为准
- 字段名以 `@ColumnInfo` 为准
- 主键、外键、可空约束、索引策略以 `Room` 为准
- 数据库版本以 `AppDatabase.version` 为准

当前正式数据库版本：

- `version = 4`

## 3. CSV 的职责

`data/seed/*.csv` 的职责只有一个：

- 维护正式 schema 对应的数据内容

CSV 不是结构权威，不负责决定表结构，也不允许自行新增、删除或改名字段。

CSV 的维护规则：

- 表头必须与正式 schema 对应
- 缺失字段必须补齐默认值或样本值
- 废弃字段必须从 CSV 中移除，不能继续保留脏列
- 后续扩充药品样本时，优先改 `CSV`，而不是直接改库文件

当前重点维护文件：

- `data/seed/drug_master.csv`
- `data/seed/drug_detail.csv`
- `data/seed/drug_rule.csv`

## 4. `build_seed_db.py` 的职责

`tools/build_seed_db.py` 只负责做构建闸门，不负责决定 schema。

脚本的固定职责是：

1. 读取 `docs/sql/drug_offline_schema.sql`
2. 按 SQL 建表
3. 导入 `CSV`
4. 校验 CSV 表头
5. 校验关键表结构
6. 校验导入后数据量
7. 输出 `app/src/main/assets/db/drugs.db`

脚本不允许做的事：

- 擅自补字段
- 静默忽略 CSV 脏列
- 在 schema 不匹配时继续生成库
- 把 `drugs.db` 当成手工维护产物

## 5. `drugs.db` 的生成方式

正式生成方式只有一种：

```bash
python tools/build_seed_db.py
```

标准生成链路：

```text
Room / AppDatabase
-> docs/sql/drug_offline_schema.sql
-> data/seed/*.csv
-> tools/build_seed_db.py
-> app/src/main/assets/db/drugs.db
```

生成要求：

- 先确认 `Room` 已更新
- 再同步 `docs/sql/drug_offline_schema.sql`
- 再同步 `CSV` 表头和数据
- 再运行脚本生成资产库

禁止操作：

- 手工修改 `app/src/main/assets/db/drugs.db`
- 直接拿历史旧库覆盖新库
- 只改 SQL 不改 `Room`
- 只改 CSV 不改脚本校验

## 6. 允许修改与禁止修改的文件

允许作为正式维护入口修改的文件：

- `app/src/main/java/com/weiguangchangxing/weiguang_plus/data/local/entity/*.kt`
- `app/src/main/java/com/weiguangchangxing/weiguang_plus/data/local/AppDatabase.kt`
- `app/src/main/java/com/weiguangchangxing/weiguang_plus/data/local/dao/*.kt`
- `app/src/main/java/com/weiguangchangxing/weiguang_plus/data/repository/*.kt`
- `docs/sql/drug_offline_schema.sql`
- `data/seed/*.csv`
- `tools/build_seed_db.py`

禁止手改的文件：

- `app/src/main/assets/db/drugs.db`

原因：

- 它是构建产物，不是源文件
- 它必须始终由正式脚本生成
- 任何手改都可能让运行时结构与源码基线再次漂移

## 7. 迁移策略说明

当前阶段运行时继续保留：

- `fallbackToDestructiveMigration()`

原因：

- 当前还处在正式迁移脚本补齐前的阶段性收敛期
- 它可以处理版本升级时的破坏性重建

但必须明确：

- 它不是 schema 不一致的解决方案
- 它不能替代 `Room / SQL / CSV / build_seed_db.py` 的同步修改
- 后续一旦补齐正式 migration，应移除该兜底策略

## 8. 以后每次改数据库结构的硬规则

以后每次改数据库结构，必须同时修改以下 5 处：

1. `Entity`
2. `AppDatabase`
3. `docs/sql/drug_offline_schema.sql`
4. `CSV` 表头
5. `tools/build_seed_db.py`

提交前至少完成以下 3 项：

1. 重建 `drugs.db`
2. 本地启动校验
3. 关键样本查询校验

## 9. 真机与构建验收标准

正式验收标准固定为：

- `python tools/build_seed_db.py` 成功
- 新生成的 `app/src/main/assets/db/drugs.db` 结构与 `Room` 一致
- `:app:assembleRelease` 成功
- 全新安装 `release` 后首次启动不闪退
- 至少 3 条样本查询通过：
  - `布洛芬`
  - `阿莫西林`
  - `二甲双胍`

运行时重点核验项：

- 首次启动数据库创建是否成功
- 查询是否能命中 `drug_master`
- 风险字段是否能正常展示
- `tts_summary` 与 `tts_message` 是否能参与播报文本拼装
- 来源追溯字段是否可见

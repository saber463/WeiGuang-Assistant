# 药品数据源实操接入教程 v1.0

## 1. 文档用途

这份文档专门给移动端开发用，目标不是讲理论，而是告诉你：

- 这 4 个药品资源到底能拿到什么
- 怎么查、怎么导、怎么转 CSV / SQLite
- 怎么塞进 Android / Flutter App
- 药品 OCR 识别后怎么接这些数据
- 哪些资源可以用，哪些资源只能参考，哪些资源当前不建议接

## 2. 先给结论

### 推荐优先级

1. `NMPA`：适合作为官方校验源，适合做标准名、批准文号、生产企业校对。
2. `DataSN 3万药品库`：适合作为离线 SQLite 基础库候选，但前提是确认购买和授权。
3. `丁香园离线资源`：适合作为离线包结构参考，不建议默认直接二次打包进你自己的 App。
4. `tngou 免费药品 API`：当前不建议接入生产，访问结果异常，可信度不足。

### 如果你现在就要做无障碍药品 OCR

最稳的做法是：

- 用 `OCR` 先识别药盒上的 `药品通用名 / 商品名 / 批准文号`
- 用 `本地 SQLite 药品库` 做主检索
- 用 `NMPA` 做药品标准名和批准文号校验
- 用 `TTS + 大字模式 + 强震动提醒` 做无障碍输出

不要一开始把所有查询都依赖在线接口，否则网络一断，整个功能就废了。

## 3. 资源一：NMPA 国家药品监督管理局数据查询

### 3.1 这个平台能拿到什么

适合拿到的药品信息：

- 药品名称
- 申请人 / 生产企业
- 批准文号
- 批准日期
- 历史药品注册进度
- 部分药品批准证明文件送达信息

从公开可见页面可以确认，NMPA 政务服务门户提供了 `历史药品注册进度查询` 入口，药品批准信息页面里能看到 `药品名称、申请人、批准文号、批准日期` 等字段。

### 3.2 官方入口

- 政务服务门户：`https://zwfw.nmpa.gov.cn/web/index`
- 历史药品注册进度查询入口：`https://zwfw.nmpa.gov.cn/web/index/ypzcjdGjj`
- 官方主页：`https://www.nmpa.gov.cn/`

### 3.3 页面实操查询步骤

#### 方式 A：人工查询

1. 打开 `https://zwfw.nmpa.gov.cn/web/index`
2. 找到 `历史药品注册进度查询`
3. 进入后按药品名称、受理号、申请人、批准文号等条件检索
4. 在结果页查看单条药品记录
5. 手工记录核心字段：
   - 药品名称
   - 企业名称
   - 批准文号
   - 批准日期

#### 方式 B：公告页抓取

如果你要做新增药品同步，可抓取 `药品批准证明文件送达信息` 公告页：

1. 打开 NMPA 网站中的药品批准相关公告
2. 解析表格字段
3. 抽取：
   - `药品名称`
   - `申请人`
   - `批准文号`
   - `批准日期`
4. 存入你自己的标准化表

### 3.4 接口情况

#### 真实情况

- `NMPA` 没有给你这类移动端开发者提供一份清晰稳定、公开可直接调用的药品 REST API 文档。
- 也就是说，你不能把它当作像标准开放平台那样直接 `GET /drug?id=xxx` 来长期依赖。
- 更现实的方式是：
  - 人工查询
  - 页面抓取
  - 定时离线同步到你自己的库

#### 开发建议

不要把 NMPA 当成 App 在线实时主查询源，而要把它当成：

- 标准数据校对源
- 批准文号校验源
- 新药增量同步源

### 3.5 可以拿到的字段

建议最少保留这些字段：

| 字段 | 用途 |
|---|---|
| `generic_name` | 通用名检索 |
| `trade_name` | 商品名补充 |
| `approval_no` | 精准匹配、OCR 命中 |
| `manufacturer` | 展示生产企业 |
| `approval_date` | 展示批准时间 |
| `source_url` | 回溯来源 |

### 3.6 如何导出为 CSV

NMPA 本身不一定给你直接下载 CSV 的按钮，所以实际做法是：

1. 用脚本抓取结果页 HTML
2. 用解析器抽表格字段
3. 输出为 CSV

示例字段顺序建议：

```csv
generic_name,trade_name,approval_no,manufacturer,approval_date,source_url
```

### 3.7 如何转为 SQLite

推荐流程：

1. 先得到 CSV
2. 用 Python 导入 SQLite
3. 导入到 `drug_master`

示例 Python：

```python
import csv
import sqlite3

conn = sqlite3.connect("drugs.db")
cur = conn.cursor()

cur.execute("""
CREATE TABLE IF NOT EXISTS drug_master (
    drug_id INTEGER PRIMARY KEY AUTOINCREMENT,
    generic_name TEXT NOT NULL,
    trade_name TEXT,
    approval_no TEXT,
    manufacturer TEXT,
    approval_date TEXT,
    source_url TEXT
)
""")

with open("nmpa_drugs.csv", "r", encoding="utf-8") as f:
    reader = csv.DictReader(f)
    rows = [
        (
            row["generic_name"],
            row["trade_name"],
            row["approval_no"],
            row["manufacturer"],
            row["approval_date"],
            row["source_url"]
        )
        for row in reader
    ]

cur.executemany("""
INSERT INTO drug_master (
    generic_name, trade_name, approval_no, manufacturer, approval_date, source_url
) VALUES (?, ?, ?, ?, ?, ?)
""", rows)

conn.commit()
conn.close()
```

### 3.8 Android / Flutter 离线接入方案

#### Android

1. 预处理生成 `drugs.db`
2. 放入 `assets/` 或首次启动下载到本地
3. 首次启动复制到应用私有目录
4. 用 `Room` 或 `SupportSQLiteOpenHelper` 打开
5. OCR 命中药名后先查 `approval_no`
6. 查不到再查 `generic_name`

#### Flutter

1. 把 `drugs.db` 放进 `assets`
2. 使用 `sqflite` 或 `sqlite3_flutter_libs`
3. 启动后把数据库复制到 `getDatabasesPath()` 目录
4. 用 `LIKE` 和批准文号匹配做本地搜索

### 3.9 在无障碍药品 OCR 中怎么接

流程建议：

1. OCR 识别药盒
2. 提取 `批准文号`
3. 优先用 `批准文号` 查本地库
4. 若没命中，再查 `通用名`
5. 返回结果后：
   - 大字展示
   - TTS 播报
   - 强震动提醒是否存在风险标签

## 4. 资源二：tngou 免费药品 API

### 4.1 当前实际情况

本次核验时，`https://www.tngou.net/api/drug` 返回内容明显不是药品 API 文档，也不是正常的药品 JSON 数据，而是无关页面内容。

这说明至少存在以下一种情况：

- 域名内容已变化
- API 已下线
- 文档地址已失效
- 站点存在被污染或被替换的问题

### 4.2 结论

`不要把 tngou 当作你们项目当前可依赖的数据源。`

### 4.3 能不能继续研究

可以，但只适合做额外调研，不适合立刻接入。

你如果仍要验证，正确动作应该是：

1. 找到站点最新首页
2. 查官方 API 文档页
3. 验证是否返回 JSON
4. 验证是否有鉴权要求
5. 验证许可协议

如果这 5 步做不到，就直接弃用。

### 4.4 当前不建议写死的内容

以下内容目前都不建议写进正式开发方案里：

- 固定 API 地址
- 固定请求参数
- 固定返回字段
- 固定离线同步脚本

因为现在无法可靠验证。

### 4.5 如果你硬要保留它，应该怎么表述

文档里只能写：

- `候选历史公开 API`
- `待人工复核`
- `不可作为正式生产主数据源`

### 4.6 在无障碍 App 里的建议定位

只作为：

- 调试阶段补样本的候选来源
- 早期原型阶段的临时网络补充源

不要作为：

- 离线主库
- 生产主检索接口
- 比赛答辩中的核心可信来源

### 5.9 适合移动端的精简策略

不要把全量原始数据不经处理就塞进 App，推荐这样裁剪：

1. 只保留高频药和慢病常用药
2. 删除不必要的原始元数据
3. 长说明书字段做压缩或分表
4. 建立别名表
5. 单独建立批准文号索引

### 5.10 Android / Flutter 离线嵌入方式

#### Android

推荐方式：

1. 先在电脑端把 CSV/JSON 清洗成 SQLite
2. 表结构贴合 `drug_master` / `drug_detail` / `drug_alias`
3. 数据库放到 `assets`
4. 首次启动复制到本地目录
5. 用 `Room` 接 Repository

#### Flutter

推荐方式：

1. 在打包前生成 `drugs.db`
2. 放入 `assets/drugs/drugs.db`
3. 启动时复制到 `sqflite` 目录
4. 用 DAO 风格封装查询

### 5.11 在无障碍药品 OCR 里的接法

建议流程：

1. OCR 提取药盒文字
2. 先提取 `批准文号`
3. 再提取 `通用名`
4. 用 `DataSN 清洗后 SQLite` 做主检索
5. 命中后展示：
   - 通用名
   - 商品名
   - 用法用量
   - 禁忌
   - 注意事项
6. 再由 TTS 播报

### 5.12 这一源的风险点

- 它不是免费公开的零门槛官方资源，存在购买和授权问题
- 页面显示需要账户、会员或购买流程，不能默认视为“可直接商用随便打包”
- 适合做你们的离线底库候选，但必须先确认授权边界

## 6. 资源四：丁香园用药助手离线资源

### 6.1 这个资源能拿到什么

页面明确写到：

- 包含临床常用药品说明书
- 支持按商品名、通用名、疾病名称、形状快速查找
- Android 版存在离线安装流程
- 离线数据包文件名为 `extra.db`

### 6.2 官方可见离线安装步骤

页面可确认的流程是：

1. 安装用药助手 Android App
2. 下载离线数据包 `extra.db`
3. 关闭 App
4. 把 `extra.db` 复制到 `SD卡/dxy/drugs/`
5. 重启 App

### 6.3 这说明了什么

这说明它的离线能力至少包含：

- 本地数据库文件
- App 启动时从固定路径读取
- 离线说明书查阅

对你们很有参考价值，因为这和你们要做的移动端离线药品查询架构非常接近。

### 6.4 能不能直接拿来做你自己的 App 资源

默认不能这么理解。

你必须区分两件事：

#### 可以做的

- 学它的离线包组织方式
- 学它把数据库放在本地路径的方式
- 学它“App + 离线 DB”分离更新的思路

#### 不能默认做的

- 直接把它的 `extra.db` 打包进你自己的作品
- 默认认为可以合法二次分发
- 默认认为可以商用或公开参赛发布

### 6.5 怎么实操研究

如果你只是研究结构，可以这么做：

## 11. 药品 OCR 识别后怎么对接这些数据源

### 11.1 推荐字段提取顺序

药盒 OCR 后优先抽这三类信息：

1. `批准文号`
2. `通用名`
3. `商品名`

### 11.2 推荐检索流程

```text
OCR -> 文本清洗 -> 批准文号匹配 -> 通用名匹配 -> 商品名匹配 -> 别名匹配 -> 模糊搜索
```

### 11.3 文本清洗建议

- 去掉空格、全角符号
- 统一括号格式
- 统一繁简和大小写

## 一、项目概述

### 1.1 项目名称
- **应用名称**：微光守护（UI 显示为"微光同行"）
- **包名**：`com.weiguangplus`
- **版本**：1.3 (versionCode 4)

### 1.2 项目定位
微光守护是一款面向**听障人士及言语障碍群体**的 Android 无障碍辅助应用。核心理念是"让沟通无界限——帮助听障人士看得见声音、说得出心意"。通过手语识别、通话辅助、紧急救助、用药识别等功能模块，帮助听障用户在日常生活、就医、出行等场景中实现信息无障碍沟通。

### 1.3 面向人群
- **听力障碍人士**：无法听到来电铃声、环境警报、门铃等声音信号
- **言语障碍人士**：无法通过口语进行电话沟通或面对面交流
- **听障老年群体**：用药安全、紧急求助等日常辅助需求

## 二、技术架构

### 2.1 整体架构
项目采用 **MVVM (Model-View-ViewModel)** 架构模式，基于以下技术栈构建：

| 层次 | 技术选型 | 说明 |
|------|---------|------|
| UI 层 | Jetpack Compose + Material3 | 声明式 UI 框架，Material Design 3 设计系统 |
| ViewModel 层 | androidx.lifecycle.ViewModel | 生命周期感知的 UI 状态管理 |
| 依赖注入 | Hilt 2.48 (kapt) | 编译时依赖注入，全局单例管理 |
| 本地存储 | Room 2.5.2 (KSP) + DataStore | Room 用于结构化数据，DataStore 用于偏好设置 |
| 网络层 | Retrofit 2.9.0 + OkHttp 4.12.0 | REST API 声明式 HTTP 客户端 |
| 机器学习 | MediaPipe + TFLite + ML Kit + Vosk | 多模型协同的端侧 AI 推理 |
| 相机 | CameraX 1.3.0 | 生命周期感知的相机预览和图像分析 |

### 2.2 应用入口
- **Application 类**：`WeiguangApplication`（`@HiltAndroidApp`），在 `onCreate()` 中初始化全局组件：
  - `TtsController.initialize()` — TTS 语音播报引擎
  - `AmbientSoundMonitor.initialize()` — 环境音监控（占位）
  - `FlashlightController.init()` — 闪光灯控制器
  - `EmergencyContactManager.init()` — 紧急联系人管理
  - `SosHistoryManager.init()` — SOS 历史记录
  - `CallStateManager(this).register()` — 通话状态监听

### 2.3 导航架构
采用 **Compose State 驱动**的轻量导航（非 Navigation Compose），通过 `MainActivity` 中的 `currentScreen` 状态变量控制页面切换。支持的路由：`home`、`chat`、`chat_detail`、`drug`、`sign`、`call`、`alert`、`sos`、`emergency_contacts`、`settings`。

## 三、功能模块清单与说明

### 3.1 手语识别模块

**职责**：通过摄像头实时捕捉手部动作，将手势翻译为文字和语音。

**核心技术栈**：
- **MediaPipe tasks-vision 0.10.2**：手部 21 关键点检测
- **TensorFlow Lite 2.14.0**：手势分类 INT8 量化模型
- **CameraX 1.3.0**：相机预览与帧分析

**核心类与实现逻辑**：

| 类名 | 职责 |
|------|------|
| `MediaPipeHandLandmarker` | 调用 MediaPipe Tasks Vision API，提取手部 21 个关键点 (x, y, z) 坐标 |
| `SignLanguageRecognizer` | 加载 TFLite INT8 量化模型（`gesture_classifier_int8.tflite`），对 63 维关键点特征进行 10 类 Softmax 分类；可选启用 30 维几何特征增强（指尖距离、关节角度等），此时输入为 93 维；模型准确率 99.28% |
| `GestureClassifier` | 基于规则的备用手势识别器，支持 20+ 日常手势（握拳/SOS、手掌张开/帮助、点赞/确认、OK、V字/胜利等），通过手指弯曲度和指尖距离判断 |
| `SignLanguageEngine` | 引擎编排器，整合三大组件：TFLite 分类 + LandmarkBuffer（60 帧时序滑动窗口）+ SignVectorDB（质心向量检索交叉验证）；实现 5 帧去抖确认和 8 帧 SOS 连续确认 |
| `SignLanguageCameraManager` | CameraX 相机管理，绑定 PreviewView 预览，逐帧分析手部检测 |
| `SignLanguageScreen` | UI 界面，含相机预览区、识别结果卡片（置信度进度条）、Top-5 候选词、手势参考库 |
| `SignVectorDB` | 手势向量数据库，质心向量检索 + 交叉验证 |
| `LandmarkBuffer` | 60 帧时序滑动窗口，取均值特征减少抖动 |
| `VoiceRecognizer` / `VoiceToSignController` | 语音转手语方向的反向翻译 |
| `SignLanguageGenerator` / `SignLanguagePlayerScreen` | 手语动画生成与播放 |

**识别流水线**：
```
摄像头帧 → MediaPipe 21 关键点 → LandmarkBuffer 缓冲（60帧）
→ 取最近10帧均值 → TFLite 分类（Top-5）→ SignVectorDB 交叉验证
→ 5帧去抖确认 → 输出结果（手势名+置信度+文字翻译+SOS标记）
```

**支持的手势**：握拳(SOS求救)、手掌张开(需要帮助)、点赞(确认)、食指指向(方向)、剪刀手(胜利)、OK(没问题)、摆手(你好/再见)、比心(谢谢)、打电话(打电话)、拇指朝下(不好/不行)。

### 3.2 通话辅助模块

**职责**：在来电/通话时实时将对方语音转为文字字幕，支持用户通过文字输入回复并 TTS 播报。

**核心技术栈**：
- **Android SpeechRecognizer**：系统内置语音识别引擎
- **Android TextToSpeech**：文字转语音
- **TelephonyManager**：通话状态监听

**核心类与实现逻辑**：

| 类名 | 职责 |
|------|------|
| `CallAssistantService` | 前台服务（foregroundServiceType="phoneCall"），显示"来电助手运行中"通知 |
| `CallStateManager` | 注册 `PhoneStateListener`，监听来电响铃(RINGING)、接听(ANSWERED)、挂断(ENDED)等状态 |
| `CallTranscriber` | 使用 `SpeechRecognizer` 进行实时中文语音识别（zh-CN），支持部分结果(partialResults)实时更新；同时管理 TTS 用于文字回复播报 |
| `CallViewModel` | MVVM 状态管理，维护通话状态、实时字幕文本、快捷短语列表 |
| `CallAssistantScreen` | UI 界面：通话状态横幅（颜色随状态变化）、实时字幕区（深色背景白色文字）、快捷回复短语（LazyRow）、文字输入框 + 发送按钮（文字转语音） |

**通话状态枚举**：IDLE(闲置) → RINGING(响铃) → ANSWERED(接通) → ENDED(挂断) / DIALING(拨号中)。

### 3.3 紧急救助 / SOS 模块

**职责**：一键触发紧急求救，自动发送含 GPS 位置的短信给紧急联系人，同时闪光灯闪烁 SOS 摩斯码、震动反馈、TTS 语音播报。

**核心技术栈**：
- **Android SmsManager**：发送求救短信
- **LocationManager**：GPS/网络定位
- **Camera2 API**：闪光灯 SOS 摩斯码闪烁
- **SensorManager (Accelerometer)**：摇一摇检测触发

**核心类与实现逻辑**：

| 类名 | 职责 |
|------|------|
| `SosManager` | SOS 核心逻辑：震动反馈 → TTS 语音播报 → 闪光灯 SOS 摩斯码(··· ─── ···) → 获取 GPS 位置 → 发送短信给所有紧急联系人 |
| `EmergencyContactManager` | 基于 SharedPreferences 的紧急联系人存储（name + phone 键值对） |
| `ShakeDetector` | 加速度传感器检测剧烈摇晃，阈值 25m/s²，1 秒内连续 3 次摇晃触发 SOS |
| `SosHistoryManager` | SOS 求救历史记录管理 |
| `SosScreen` | UI：就绪视图(READY) → 3 秒倒计时(COUNTDOWN，可取消) → 结果视图(RESULT，含位置坐标、地图打开、紧急拨号 110/120/119) |
| `QuickSettingsTileService` | 系统快捷设置磁贴，通知栏下拉一键触发 SOS |

**SOS 短信内容**：
```
【SOS紧急求助】一位听障人士发出了求救信号！
位置坐标：{latitude},{longitude}
请尽快联系确认安全！
—— 来自微光同行APP
```

### 3.4 用药识别模块

**职责**：通过拍照药品包装盒，使用 OCR 识别文字，匹配药品库并评估风险等级。

**核心技术栈**：
- **ML Kit text-recognition-chinese 16.0.0**：中文字符 OCR 识别
- **ML Kit object-detection 17.0.0**：通用物体检测
- **Room**：识别历史记录存储
- **Retrofit**：后端药品识别 API

**核心类与实现逻辑**：

| 类名 | 职责 |
|------|------|
| `EnhancedOcrEngine` | OCR 结果后处理引擎：文本清洗 → 模糊匹配药品库（50+ 常见药品，含感冒药/解热镇痛/抗生素/胃药/心血管/糖尿病等）→ 提取剂量/批号/生产日期/有效期 → 风险等级评估（high/medium/low）→ 生成用药警告 |
| `DrugRecognitionScreen` | UI：拍照识别 / 相册选择按钮、识别结果卡片（药品名+风险等级）、历史记录列表 |
| `DrugViewModel` | MVVM 状态管理，调用 `DrugRepository` 进行识别 |
| `DrugRepository` | 数据仓库，调用后端 API 或本地 OCR |
| `WeiguangApiService` | 后端 API：`POST /api/drugs/recognize`（图片上传识别）、`GET /api/drugs/history`（历史记录）、`GET /api/drugs/search`（药品搜索）等 |

**药品库覆盖**：感冒药(999感冒灵、连花清瘟等)、解热镇痛药(布洛芬、阿司匹林等)、抗生素(阿莫西林、头孢等)、胃药(吗丁啉、奥美拉唑等)、肠道用药、止咳药、维生素/补充剂、外用药、心血管药、糖尿病药、抗过敏药。

### 3.7 TTS 语音播报

**职责**：封装 Android TextToSpeech API，为各模块提供统一的语音播报能力。

**核心类**：`TtsController`（object 单例）

**功能**：
- 异步初始化（等待 TTS 引擎就绪）
- 中文语言设置（不支持时回退到默认语言）
- 队列播报（QUEUE_ADD，防止同时播放）
- 紧急播报（QUEUE_FLUSH，打断当前语音，提高语速至 1.2x）
- 语速/音调可调（默认语速 0.9，音调 1.0）
- 播报进度回调（UtteranceProgressListener）

### 3.9 OCR 文字识别

**职责**：使用 ML Kit 中文字符识别引擎，从图片中提取文字内容，用于药品包装识别。

### 3.10 闪光灯控制

**职责**：控制设备 LED 闪光灯，用于来电闪烁、闹钟闪烁、SOS 警示等视觉提醒场景。

**核心类**：`FlashlightController`（object 单例）

**功能**：
- `init()`：查找支持闪光灯的后置摄像头 ID
- `turnOn()` / `turnOff()` / `toggle()`：开关闪光灯
- `blink(times, onMs, offMs)`：指定次数和间隔闪烁
- `sosBlink()`：SOS 摩斯码闪烁（三短三长三短）

**技术**：Camera2 API `setTorchMode()`，兼容 Android 6.0+。

```bash
# 输出 APK 路径

```

### 5.3 特殊构建配置

1. **jniLibs 手动管理**：AGP 8.2.0 存在 BUG，AAR 中的 `.so` 文件不会自动打包进 APK。需手动从 AAR 提取 `.so` 文件到 `src/main/jniLibs/{abi}/` 目录。涉及的库：`libmediapipe_tasks_vision_jni.so`、`libmlkitcommonpipeline.so`。

2. **TFLite/MediaPipe 模型不压缩**：`.tflite` 和 `.task` 文件在 APK 中以 STORED（不压缩）方式存储，确保运行时通过 mmap 直接读取模型文件。

3. **NDK strip 禁用**：在沙箱环境中 `llvm-strip` 命令因权限限制无法启动，通过 `tasks.matching` 禁用 `stripDebugDebugSymbols` 任务。影响：调试版 APK 体积稍大（约 10-20MB），不影响功能。

4. **Room 使用 KSP 而非 kapt**：避免 kapt 与 Kotlin suspend 函数的兼容性问题（"Not sure how to convert a Cursor" 编译错误）。

5. **Hilt 使用 kapt**：Hilt 2.48 对 KSP 支持不稳定，仍使用 kapt 处理注解。

## 六、后续规划

基于功能对标调研报告（《听障/言语障碍/无障碍辅助类 APP 功能对标与可借鉴清单》），提炼以下 Roadmap：

### 第一优先级（借鉴价值高 + 实现难度中 + 契合度高）

| 编号 | 功能 | 做什么 | 实现路径 |
|------|------|--------|---------|
| G1 | 声音事件分类提醒 + 自定义声音训练 | 将环境音监控从"检测到声音"升级为"识别是什么声音（门铃/警报/婴儿哭/电话铃）"，支持用户录制自定义声音训练识别，触发振动+闪光+弹窗多模态提醒 | 扩展现有 `AmbientSoundMonitor` + TFLite 声音分类模型（Google Audio Set 预训练微调），与闪光灯控制模块联动 |
| G2 | 全场景悬浮窗实时字幕 | 在任意应用上方悬浮显示实时语音转文字字幕，覆盖面对面交流、会议、看视频等全场景 | 扩展现有通话转写能力，基于 Vosk + Android Service (WindowManager TYPE_APPLICATION_OVERLAY) 实现系统级悬浮窗 |
| G3 | 言语康复/构音训练模块 | 为听障/言语障碍用户提供音素级发音评估、错误定位、口型动画引导、动作级纠正建议 | 新建模块：Vosk 做发音评估 + MediaPipe FaceMesh 做唇形检测 + Canvas 口型动画 + Room 训练进度管理 |

### 第二优先级（借鉴价值中 + 实现难度低 + 契合度高）

| 编号 | 功能 | 做什么 | 实现路径 |
|------|------|--------|---------|
| G4 | 转录历史存储与 AI 摘要 | 保存通话/对话转录记录，支持按时间回溯查看，AI 生成对话摘要 | Room 存储转录文本 + Retrofit 对接大模型 API 生成摘要 |
| G6 | 振动模式反馈 | 根据不同声音事件类型/紧急程度，输出不同强度和频率的振动模式 | Android Vibrator API 原生支持，与闪光灯控制并行 |
| G7 | 手语学习/词典/纠错模块 | 面向用户的手语学习功能：手语词典查询、学习教程、练习纠错反馈 | 复用现有手语向量库和 MediaPipe 手部关键点检测能力 |
| G9 | 紧急联系人自动短信/呼叫 | 检测到紧急声音事件（如火灾警报）时自动向预设紧急联系人发送短信通知+位置 | 扩展 SOS 模块，与 G1 声音分类触发联动 |
| G12 | 快捷短语/常用语输入 | 预设常用短语库（如"请帮我叫医生""我要挂号"），一键输入发送 | 纯 Kotlin/Room 实现，与现有聊天模块和 TTS 模块结合 |

### 暂缓方向（难度高/契合度低）

- G13 无障碍出行导航（需地图数据，契合度低）
- G14 远程真人手语翻译（需运营团队，非技术问题为主）
- G15 视频会议字幕集成（需对接第三方会议 SDK）

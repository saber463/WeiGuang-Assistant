## 一、调研背景与目的

### 1.1 宏观背景

根据中国残疾人联合会数据，我国听力障碍人群约 **2780万**，言语障碍人群约 **1300万**，合计超过 **4000万**。这一群体在日常生活、安全防护、医疗用药、紧急求助等方面面临严峻挑战：

- **听觉信息缺失**：无法感知火灾警报、燃气泄漏声音、敲门声、婴儿啼哭等环境音
- **沟通障碍**：无法通过电话/语音与外界沟通，紧急求助能力受限
- **用药风险**：无法阅读药品说明书或听取用药指导，存在误服、过敏风险
- **安全隐患**：跌倒后无法呼救，独居场景下风险极高
- **数字鸿沟**：现有APP大多以听觉/语音交互为核心，对听障人群不友好

### 1.2 调研目的

微光科技团队于2026年6月启动针对听障及言语障碍人群的深度功能调研，旨在：

1. 精准识别听障/言语障碍人群在日常生活场景中的**真实痛点**
2. 评估现有辅助技术产品的**覆盖盲区**
3. 验证微光守护（SafeGuard）核心功能的**需求匹配度**
4. 为产品迭代方向提供**数据支撑**

- **高度依赖视觉通道**：手机屏幕、闪光灯、震动是主要信息接收方式

- **安全意识薄弱**：多数受访者表示曾因听不到警报而遭遇危险场景
- **对科技产品接受度高**：11人（84.6%）表示愿意尝试智能辅助设备
- **价格敏感**：月均可支配收入多在2000-5000元区间

| 🚌 出行 | 公交/地铁到站无法获取语音提示 | 🟡 重要 | 69.2% | 看窗外/记站数 | 夜间/拥挤时容易错过 |
| 🔒 隐私安全 | 担心监控数据泄露 | 🟠 严重 | 53.8% | 不使用智能设备 | 因噎废食 |

### 3.2 关键发现

1. **安全>沟通>便利**：受访者最担心的是"听不到危险"，其次才是"说不出话"
2. **独居人群风险最高**：5位独居受访者全部表示曾经历过危险场景（火灾隐患、燃气泄漏、跌倒）
3. **现有方案覆盖率极低**：多数痛点无有效解决方案，或方案成本过高/操作复杂
4. **隐私是隐性门槛**：超过半数受访者担心监控数据被滥用，尤其涉及家庭摄像头和音频采集

## 四、现有解决方案对比

### 4.1 竞品分析

| 产品 | 类型 | 核心功能 | 价格 | 优势 | 不足 |
|------|------|---------|------|------|------|
| 小米可视门铃 | 硬件 | 门口画面+手机通知 | 199-399元 | 品牌可靠/安装简单 | 仅为单一场景/无安全告警 |
| 涂鸦智能烟雾报警器 | 硬件 | 烟雾检测+APP推送 | 99-199元 | 专业烟雾检测 | 无燃气/火灾音频联动/依赖手机通知 |
| Google Live Transcribe | 软件 | 实时语音转文字 | 免费 | 识别准确/支持多语言 | 仅单向/需对方说话/无手语支持 |
| 音书 | 软件 | 语音转文字+手语翻译 | 免费+会员 | 中文场景优化 | 手语翻译准确度有限/无安全功能 |
| 华为AI字幕 | 软件 | 系统级语音转文字 | 免费（华为手机） | 系统级集成/低延迟 | 仅华为手机/无双向手语 |
| Apple Watch 跌倒检测 | 硬件+软件 | 自动跌倒检测+紧急呼叫 | 2999元起 | 精准/自动触发 | 价格高/仅iOS生态/无后续安全联动 |
| 聋人闹钟APP | 软件 | 震动+闪光闹钟 | 免费 | 专注单一场景 | 功能单一/无安全功能 |

### 4.2 市场空白

**目前市面上没有一款产品同时覆盖"沟通+安全+用药+唤醒"四大场景**。现有产品呈现以下特点：

1. **碎片化**：每个产品仅解决1-2个痛点，用户需安装多个APP
2. **硬件依赖高**：智能硬件方案成本高、安装复杂、维护困难
3. **缺乏安全闭环**：多数产品仅提供"通知"，不提供"联动响应"
4. **手语支持薄弱**：手语翻译准确率低、词汇量有限、无双向转换
5. **隐私保护不足**：数据上传云端，用户无法控制

### 5.2 功能详情

#### P0 核心功能（必须实现）

**1. 火灾/燃气安全检测（92.3%支持率）**
- 通过麦克风实时采集环境音频，TFLite本地模型推理识别火灾警报声、燃气泄漏声
- 检测到危险时触发：全屏红色+震动+闪光灯+SOS语音播报
- 所有处理在设备本地完成，不上传音频数据

**2. 双向手语翻译（84.6%支持率）**
- 摄像头采集手语手势 → MediaPipe 21关键点检测 → 手势分类 → 文字+语音输出
- 支持30+高频日常短语（"我要喝水""请帮帮我""不舒服"等）
- 反向：语音/文字输入 → 手语动画（Canvas绘制 + Lottie增强）
- 内置100+常用词汇手语映射表

**3. 跌倒检测（76.9%支持率）**
- 加速度计+陀螺仪实时监测，TFLite模型识别跌倒特征
- 自动触发：短信通知紧急联系人+GPS定位+闪光灯SOS信号
- 30秒内可手动取消，防止误报

**4. 三重强提醒闹钟（76.9%支持率）**
- 震动模式：自适应4级强度（低/中/高/紧急）
- 闪光灯：频闪联动（亮度+频率递增）
- 铃声：最大音量+强制解除静音
- 通知栏关闭通道+长按10秒解闭

#### P1 扩展功能（基于调研需求开发）

**5. 药品OCR识别（76.9%支持率）**
- CameraX拍照 → ML Kit OCR文字提取 → 药品名称匹配
- 内置80+常见药品关键词库
- 过敏原自动匹配、用药禁忌校验
- TTS语音播报药品信息

**6. 敲门/环境音识别（84.6%支持率）**
- 持续环境音频采集，分类：敲门声/人声/音乐/警报/静音
- 检测到敲门→视觉闪烁提醒+手语短语面板快速弹出
- 检测到人声→提示"有人在说话"

**7. 紧急一键求助（84.6%支持率）**
- 一键发送：预置求助短语+GPS定位+紧急联系人
- 短信+APP推送双通道
- 支持预设多条求助内容

#### P2 规划功能

**8. 咳嗽/呼吸异常监测（61.5%支持率）**
**9. 公交地铁到站提醒（69.2%支持率）**
**10. 语音转手语反向翻译（53.8%支持率）**

```
├─────────────────────────────────────────────────┤

├─────────────────────────────────────────────────┤
│  安全层     │ WeiGuang-Secure 端到端加密           │
├─────────────────────────────────────────────────┤
│  硬件层     │ CameraX │ AudioRecord │ 传感器 │ GPS  │
└─────────────────────────────────────────────────┘
```

### 6.2 关键技术选型

| 技术 | 用途 | 选型理由 |
|------|------|---------|
| MediaPipe Hand Landmarker | 手语手部21关键点检测 | Google官方/离线/高精度 |
| TensorFlow Lite | 音频分类（火灾/燃气/咳嗽/敲门） | 轻量/移动端优化/离线 |
| ML Kit OCR | 药品包装文字识别 | 中文优化/离线/免费 |
| CameraX | 相机图像采集 | Jetpack官方/生命周期感知 |
| AudioRecord | 环境音频采集 | 低延迟/16kHz单声道/PCM |
| Room + KSP | 本地数据库 | 离线/类型安全/协程支持 |
| WeiGuang-Secure | 端到端加密 | ECDH X25519 + AES-256-GCM + TEE |

### 6.3 隐私保护策略

- **所有AI推理在设备本地完成**，音频、视频、传感器数据不上传服务器
- 端到端加密：ECDH X25519 + AES-256-GCM/ChaCha20-Poly1305双引擎
- Android Keystore TEE生物特征绑定
- 零知识架构：服务器无法解密任何用户数据
- 核心算法开源（Apache 2.0）

### 6.4 设备兼容性

- 最低支持：Android 7.0（API 24），覆盖2016年至今几乎所有Android设备
- 目标版本：Android 14（API 34）
- 手语识别：高端机型全精度模型，低端机型轻量模型（模型蒸馏保证准确率一致）
- 适配：小米、华为、OPPO、vivo等主流品牌

## 八、结论与建议

### 8.1 核心结论

1. **需求真实且迫切**：4000万听障/言语障碍人群的安全、沟通、用药痛点长期被忽视，市场存在巨大空白
2. **微光守护定位精准**：基于13位真实用户调研，92.3%的功能支持率验证了产品方向
3. **技术方案可行**：离线AI推理+端到端加密+低成本硬件方案，兼顾效果与隐私
4. **差异化明显**：市面上唯一同时覆盖"沟通+安全+用药+唤醒"四大场景的一站式解决方案

### 8.2 建议

1. **优先打磨P0核心功能**：火灾/燃气检测、手语翻译、跌倒检测、三重闹钟
2. **强化隐私保护宣传**：将"数据不出设备"作为核心卖点，打消用户顾虑
3. **降低使用门槛**：针对老年用户优化UI，提供首次使用引导
4. **建立用户反馈闭环**：定期收集听障用户真实使用反馈，持续迭代
